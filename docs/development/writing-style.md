# 表記規約

## 目的

コードコメントと文書の記号表記を揃える。全角・半角が混在すると読みづらい。また全角の約物は Markdown の強調を壊す原因にもなる。

本規約で定めるのは、機械的に判定できる表記だけである。文章の書き方 (何を書くか) は、コメントについては [コーディング規約](./rules.md) の「コメント」を、docs については各ドキュメントの方針を参照する。

## 適用範囲

- **対象**
    - Markdown: `docs/`、`tasks/`、`CLAUDE.md`、スキル、エージェント定義など
    - コードコメント (JSDoc を含む)
    - Claude の出力: PR 説明、Issue、コメント、コミットメッセージ
- **対象外**
    - コード中の文字列リテラル: UI 文言、エラーメッセージ、テスト名など。画面に出る文言の表記は UX 側で判断する

## 1. 記号は半角で書く

| 半角にする記号 | 全角のままにする記号 |
|---|---|
| `(` `)` `:` `/` `?` `!` `+` `=` `&` `%` | `「」` `『』` `、` `。` `・` `→` `〜` |

全角のままにするのは、日本語の文章構造を担う約物と、半角に置き換えるものがない記号である。

## 2. スペースは記号の役割で決める

記号を役割で 3 つに分け、役割ごとに半角スペースを入れる位置を決める。

| 役割 | 記号 | スペースの位置 | OK | NG |
|---|---|---|---|---|
| 挟む | `+` `=` `/` `&` | 前後 | `a + b`、`起票 / オーケスト` | `a+b`、`起票/オーケスト` |
| 囲む | `(` `)` | カッコの外側のみ | `実装担当 (Sonnet) に渡す` | `実装担当(Sonnet)に渡す`、`( Sonnet )` |
| 区切る | `:` `?` `!` | 後ろのみ | `目的: 速度改善` | `目的 : 速度改善`、`目的:速度改善` |

## 3. 例外

次の場合は、上の規則よりも優先する。

1. **記号が語の一部になっているときは詰める**
    - 記号が文を区切ったり項をつないだりせず、ひとまとまりの語や値を作っている場合
    - 例: 比率 `2:3`、時刻 `12:30`、日付 `2026/09/27`、分数 `1/2`、割合 `50%`、`A/B テスト`、`TCP/IP`、`and/or`
2. **行頭・行末、全角の約物と隣り合う側にはスペースを入れない**
    - 例: `〜する (補足)。`、`「設定 (任意)」`、`(例: 値)`
    - スペースを重ねない
3. **コード表現の中は対象外**
    - インラインコード、コードブロック、URL、ファイルパス、glob、識別子
    - Markdown の構文そのもの (リンクの `[]()`、表の `|`、強調の `**` など)

## 4. Markdown の強調

CommonMark (GitHub も同じ仕様) では、強調の開始・終了の `**` が約物と文字に挟まれると、強調として認識されない。`**` がそのまま表示される。日本語は約物の直後に空白を置かずに文が続くため、この条件を頻繁に満たしてしまう。

- **強調は約物の内側に置く**
    - OK: `「**重要**」だ`
    - NG: `**「重要」**だ`
- **カッコを含めて強調するときは、半角カッコの外側のスペースで区切る**
    - OK: `**実装担当 (Sonnet)** に渡す`
    - NG: `**実装担当（Sonnet）**に渡す`
    - 2 章のスペース規則に従っていれば、このケースは自然に避けられる
- **インラインコードを丸ごと強調で包まない**
    - `` **`code`**で `` は壊れる。強調したい場合は前後の日本語側で調整する
- **文字どおりの `*` / `**` / `_` はコード化する**
    - 例: glob の `integration/**`、`**kwargs`
    - `\*\*` のエスケープで済ませず、インラインコードにする
