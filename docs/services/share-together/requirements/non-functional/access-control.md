# アクセス制御

Share Together の操作を、誰に許すかの要件。判定の基準と、画面を経由しない API の呼び出しへの扱いを定める。

## 要求水準

- 判定は、プラットフォームのロールではなく、次の 3 つで行う。Auth のロールや権限は使わない
    - ログインしていること
    - グループでの立場 (承認済みか、オーナーか)。立場の定義は[グループの立場](../../specs/term/group-role.md)
    - リストの持ち主
- ログインしていない利用者は、どの画面もサインインへ送り、API は 401 を返す ([API のエラー応答](../../specs/term/api-error.md))
- 個人リストと、その ToDo は、持ち主だけが読み書きできる。他人のリストは存在しないものとして扱う ([個人リスト API](../../specs/api/personal-lists.md))
- グループの共有リストと ToDo は、そのグループの承認済みのメンバーだけが読み書きできる。招待中・拒否済みの人や、メンバーでない人は拒否する ([共有リスト API](../../specs/api/group-lists.md))
- グループの名前の変更・削除、メンバーの招待、ほかのメンバーの除外は、オーナーだけが行える ([グループ API](../../specs/api/groups.md)、[グループメンバー API](../../specs/api/group-members.md))
- 非メンバーが画面を経由せずに API を直接呼んでも、拒否する。画面の表示や操作の制限だけに頼らず、API で判定する

## やらないこと

なし
