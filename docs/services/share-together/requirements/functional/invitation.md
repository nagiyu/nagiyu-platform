# 招待

オーナーがメールアドレスで利用者をグループへ招待し、招待された利用者が承認か拒否で応じられるようにする。ユースケースは[グループを作って人を招待する](../use-cases/create-group-and-invite.md)と[招待に応じる](../use-cases/respond-to-invitation.md)。

## 要件

- オーナーが、利用者として登録されている相手のメールアドレスで、招待できる。メールアドレスの大文字と小文字は区別しない
- 招待された利用者が、招待の画面で、自分宛ての招待の一覧を見られる。未処理の招待の件数も、画面で知らせる ([招待画面](../../specs/screen/invitations.md))
- 招待された利用者が、招待を承認または拒否できる。承認するとグループのメンバーになる
- 招待は、招待した日時から 24 時間で期限が切れる。期限切れの招待は、一覧に出ず、承認も拒否もできない
- 拒否した相手や、期限が切れた相手には、改めて招待できる
- 招待の人数の扱いは、グループの人数の上限に従う ([グループ](group.md))
- 招待はメールでは知らせない。サービス内の通知で知らせる
- 招待を受け取る側の画面は、画面を開いたときに最新を読む。自動では更新しない ([目的](../purpose.md))

今の挙動は[招待](../../specs/term/invitation.md)、[招待 API](../../specs/api/invitations.md)、[招待画面](../../specs/screen/invitations.md)、[招待から参加までの経路](../../specs/flow/group-invitation.md)にある。

## やらないこと

- **メールでの招待の通知**: サービス内の通知で足り、SES や SNS などのインフラを足さずに済むため
