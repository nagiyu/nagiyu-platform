# Share Together 要件定義

この文書は、何を満たすべきか (目的・対象利用者・要件) を書く。今どう動くかは[仕様カード](../../specs/README.md)にあり、各節からリンクする。

## 1. サービスの目的

### 1.1 背景

Share Together では個人 ToDo リストの名前変更・削除が可能だが、共有リストには同等の操作手段がなかった。グループメンバーが共有リストを自由に整理できるようにするため、共有リストの名前変更・削除機能を追加する。

### 1.2 対象ユーザー

- **プライマリーユーザー**: Share Together にログイン済みの、グループの承認済みメンバー

### 1.3 ビジネスゴール

- 個人リストと同等の操作性を共有リストにも提供し、ユーザー体験の一貫性を確保する

---

## 2. 機能要件

### 2.1 ユースケース

#### UC-001: 共有リスト名の変更

- **概要**: グループの承認済みメンバーが、共有リストの名前を変更する
- **アクター**: 承認済みグループメンバー
- **前提条件**: 対象グループのメンバーシップが `ACCEPTED` 状態であること
- **今の挙動**: [リスト画面](../../specs/share-together/screen/lists.md)、[共有リスト API](../../specs/share-together/api/group-lists.md)

#### UC-002: 共有リストの削除

- **概要**: グループの承認済みメンバーが、共有リストを削除する
- **アクター**: 承認済みグループメンバー
- **前提条件**: 対象グループのメンバーシップが `ACCEPTED` 状態であること
- **今の挙動**: [リスト画面](../../specs/share-together/screen/lists.md)、[共有リスト API](../../specs/share-together/api/group-lists.md)

### 2.2 機能一覧

| 機能 ID | 機能名 | 説明 | 優先度 |
| ------- | ------ | ---- | ------ |
| F-001 | 共有リスト名の変更 | 承認済みメンバーが共有リストの名前を変更できる | 高 |
| F-002 | 共有リストの削除 | 承認済みメンバーが共有リストを削除できる（配下の ToDo も削除） | 高 |

### 2.3 想定画面の概要

- リスト一覧画面（共有スコープのサイドバー）([リスト画面](../../specs/share-together/screen/lists.md))

---

## 3. 非機能要件

### 3.1 パフォーマンス要件

| 項目 | 要件 |
| ---- | ---- |
| 応答時間 | 既存の個人リスト操作と同等（2秒以内） |

### 3.2 セキュリティ要件

- グループの承認済みメンバー（`status = ACCEPTED`）のみが編集・削除操作を実行できる
- API 側でメンバーシップチェックを行い、非メンバーのリクエストは拒否する (エラーは[共有リスト API](../../specs/share-together/api/group-lists.md)を参照)

### 3.3 可用性要件

既存サービスの稼働要件に準ずる。

### 3.4 保守性・拡張性要件

- 個人リストと共有リストの操作インターフェースを統一し、サイドバーコンポーネントの再利用性を維持する

---

## 4. ドメインオブジェクト

| エンティティ | 説明 |
| ----------- | ---- |
| GroupList | グループに紐づく共有 ToDo リスト |
| GroupMembership | ユーザーとグループの紐付け（ACCEPTED のメンバーのみ操作可能） |

---

## 5. スコープ外

- グループオーナーのみが操作可能にする権限管理の細分化（全メンバーが操作可能とする）
- 削除した共有リストの復元
- 個人リスト操作ロジックの変更

---

## 6. 受け入れ基準

- 共有スコープのサイドバーから、共有リストの名前変更と削除ができる
- 名前を変更すると、サイドバーの表示名が更新される
- 削除すると、リストがサイドバーから消え、別のリストがあればそこへ移る
- 操作の成功・失敗がユーザーに通知される
- 非メンバーが直接 API を呼び出しても拒否される
