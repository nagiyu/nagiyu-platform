# Stock Tracker 要件定義書

## 1. ビジネス要件

### 1.1 背景・目的

**背景**:
- 株式投資において、タイムリーな価格情報と適切なタイミングでの売買判断が重要
- 既存の finance リポジトリで提供していた株価追跡・通知機能を、本プラットフォームで刷新
- モノレポ構成による開発効率向上、共通インフラ活用によるコスト削減を目指す
- 投資判断の材料は、AI による予測ではなく、機械的に算出できる判断軸と、その過去の成績から出す。AI の予測に予測力がなかったためである (`architecture.md` ADR 2.21)

**目的**:
- リアルタイムな株価データの可視化（チャート表示）
- 条件ベースのアラート・通知による売買タイミングの最適化
- 保有株式の管理と目標価格の算出による投資判断支援
- 日次サマリーで、判断軸から算出した確度 (翌営業日についての確率) と、その出どころ (点灯した軸と各軸の過去成績) を示し、人が検討できるようにする

### 1.2 対象ユーザー

**プライマリーユーザー**:
- 個人投資家（株式トレーダー）
- 日々の株価変動をチェックし、売買判断を行うユーザー

**ユーザー特性**:
- 複数の銘柄を監視している
- 価格条件に基づいた通知を受け取りたい
- 保有株式の平均取得価格と目標価格を把握したい
- モバイル/デスクトップの両方から利用する

### 1.3 ビジネスゴール

**実装済み機能**:
1. **株価の可視化**: リアルタイムな株価データをチャートで表示
2. **通知機能**: 価格条件に基づくアラート通知
3. **保有株式管理**: 平均取得価格、目標価格の算出
4. **確度の提示**: 判断材料の出どころをすべて説明できる状態にし、確度が実際にその確率で当たっているかを継続的に確かめられる

**将来の拡張候補**:
- テクニカル指標の追加（移動平均、ボリンジャーバンドなど）
- ポートフォリオ分析機能

## 2. 機能要件

### 2.1 ユースケース

#### UC-001: 株価チャート表示

**概要**: ユーザーが指定した取引所・ティッカーの株価チャートを表示する

**アクター**: ログインユーザー

**前提条件**:
- ユーザーがログイン済み
- 取引所・ティッカーが登録されている

**正常フロー**:
1. ユーザーがトップ画面にアクセス
2. 取引所を選択
3. ティッカーを選択
4. 時間枠を選択（5分足、1時間足、日足など）
5. システムが TradingView API から株価データを取得
6. ECharts でインタラクティブなチャートを表示

**URL パラメータによる初期選択**:
- URL クエリパラメータ `exchangeId` および `tickerId` を指定すると、画面ロード時に対応する取引所・ティッカーが自動選択された状態で表示される
- Web Push 通知クリック時はこの URL を使用し、通知元アラートの取引所・ティッカーが選択済みの状態でチャートを表示する

#### UC-002: アラート設定

**概要**: ユーザーが株価の条件を設定し、条件達成時に通知を受け取る。アラートの作成・修正・削除は、アラート一覧画面（SCR-003）に加えて、トップ画面（SCR-001）のアラートパネルからも行える。

**アクター**: ログインユーザー

**前提条件**:
- ユーザーがログイン済み
- ブラウザで通知許可が有効

**正常フロー**:
1. ユーザーがアラート設定画面にアクセス
2. 取引所とティッカーを選択
3. 条件タイプを選択（価格が指定値を上回る/下回る）
4. 目標価格を入力（入力に応じてチャートオーバーレイが即時更新される）
5. 通知頻度を選択
6. 通知設定ダイアログを開き、通知タイトル・通知本文を入力する
    - デフォルトは入力内容をもとに自動生成された値が設定される
    - 条件や価格を変更した場合は本文の上書き確認ダイアログが表示される
7. システムがアラート設定を保存

#### UC-003: 保有株式管理

**概要**: ユーザーが保有株式を登録し、平均取得価格と目標価格を確認する。保有株式の作成・修正・削除は、保有株式管理画面（SCR-002）に加えて、トップ画面（SCR-001）の保有株式パネルからも行える。

**アクター**: ログインユーザー

**正常フロー**:
1. ユーザーが保有株式管理画面にアクセス
2. 新規登録ボタンをクリック
3. 取引所、ティッカー、保有数、平均取得価格を入力
4. システムが保有株式情報を保存
5. 目標価格を自動算出して表示

#### UC-004: 日次サマリー閲覧

**概要**: ユーザーが各取引所に登録されたティッカーの直近の日次サマリーを、確度とあわせて一覧形式で確認する

**アクター**: ログインユーザー（`stocks:read` 権限保持者）

**前提条件**:
- ユーザーがログイン済み
- 取引所・ティッカーが登録されている

**正常フロー**:
1. ユーザーがサマリー一覧画面にアクセス
2. システムが各取引所の最新保存済みサマリー・その日の確度・ユーザーのアラート情報を取得する（当日分が未生成の場合は直近保存済み日付のデータを表示し、空表示にしない）
3. 市場 (JP・US) ごとの荒れ予報と、ティッカーごとの方向・荒れの確度と点灯数が表示される
4. 方向・荒れの確率で並べ替えられる
5. サマリーデータが存在しない取引所は空状態メッセージを表示する

**例外フロー**:
- 確度がない日付、確度を算出できなかった銘柄は、確度の欄を「—」にする。OHLCV・パターンは通常どおり表示する

#### UC-005: 日次サマリー自動生成

**概要**: システムが 1 時間間隔の専用バッチを実行し、取引時間が終了した取引所の全ティッカーについて日次サマリーを自動生成して保存する

**アクター**: システム（EventBridge Scheduler）

**正常フロー**:
1. バッチが 1 時間間隔で実行される
2. 全取引所に対して取引時間終了を判定する（取引所のタイムゾーンを考慮）
3. 取引時間が終了した取引所について、取引所に紐づく全ティッカーの当日 OHLC データを TradingView API から取得する
4. 取得した OHLC データとパターン分析の結果を日次サマリーとして DynamoDB に保存する（同一ティッカー・同一日付は上書き更新で冪等性を保証）
5. 実行の終了時に、確度の算出 (UC-011) を起動する
6. エラーが発生した場合はログに記録し、当該ティッカー・取引所の処理をスキップして他の処理を継続する

**代替フロー**: 対象日の日足が存在しない場合（祝日などの休場日）は、日次サマリーを作らない。バッチの実行が翌営業日の取引時間中にずれ込んだ場合も、進行中の足ではなく対象日の足を使う（判断の詳細は `architecture.md` § 2.19 を参照）

**スコープ**:
- サマリーデータ項目は OHLCV（始値・高値・安値・終値・出来高）とパターン分析の結果とする
- 本バッチはアラート用の既存 1 時間バッチ（`hourly.ts`）とは独立した別バッチとして運用する

#### UC-006: 確度の詳細閲覧

**概要**: ユーザーが詳細ダイアログで、1 銘柄の確度を、ふだんの割合・同じ確率帯の過去実績・点灯した軸の内訳とあわせて確認する。表示された確率を信じてよいかと、何が確率を動かしたかを判断できるようにする

**アクター**: ログインユーザー（`stocks:read` 権限保持者）

**前提条件**:
- ユーザーがログイン済み
- 日次サマリーが生成済み

**正常フロー**:
1. ユーザーがサマリー一覧の行、またはトップ画面のサマリーパネルの詳細ボタンから詳細ダイアログを開く
2. システムが問いごと (方向・荒れ) の確率・ふだんの割合・同じ確率帯の過去実績を表示する
3. 軸ごとに、値・過去成績 (件数・的中率・ふだんとの差)・確率への寄与を表示する。件数不足で重みがゼロ寄りの軸は、その状態がわかるように表示する
4. 日足チャートを表示し、アラート作成ができる

**例外フロー**:
- 確度がない場合は、内訳の代わりに理由を表示する。チャートとアラート作成は通常どおり使える

#### UC-007: アラート絞り込み

**概要**: ユーザーがアラート一覧画面で取引所またはモードを指定してアラートを絞り込む

**アクター**: ログインユーザー

**前提条件**:
- ユーザーがログイン済み
- アラートが1件以上登録されている

**正常フロー**:
1. ユーザーがアラート一覧画面にアクセス
2. 取引所フィルタまたはモードフィルタを選択する
3. システムが選択条件に一致するアラートのみを一覧に表示する
4. ユーザーがクリアボタンを押すと全件表示に戻る

**スコープ**:
- フィルタリングはクライアントサイドで処理する
- 取引所・モードフィルタは同時に適用できる
- フィルタ状態は URL パラメータには反映しない（ページリロード時にフィルタ状態は保持されない。URL 同期が必要な場合は後続 Issue で対応する）

#### UC-008: チャート自動更新

**概要**: ユーザーがチャート画面で自動更新を有効にすると、10秒ごとにチャートデータが再取得・再描画される

**アクター**: ログインユーザー

**前提条件**:
- ユーザーがログイン済み
- 取引所・ティッカーが選択済み

**正常フロー**:
1. ユーザーがチャート表示エリアの自動更新ボタンをオンにする
2. システムが 10 秒ごとにチャートデータを再取得・再描画する
3. ユーザーが自動更新ボタンをオフにすると、自動更新が停止する

**例外フロー**:
- ティッカーが未選択の場合、自動更新を開始しない
- 取引所またはティッカーを変更しても、自動更新の有効/無効状態を維持する

**スコープ**:
- 自動更新のデフォルト値はオフ
- 自動更新中はボタンの状態変化でユーザーにフィードバックする
- コンポーネントのアンマウント時にタイマーをクリアし、メモリリークを防ぐ

#### UC-011: 確度の算出と採点

**概要**: 日次サマリーが揃った市場について、前営業日の確度を採点し、重みを更新し、当日の確度を算出する

**アクター**: システム（確度算出バッチ Lambda）

**前提条件**:
- 対象市場の当日の日次サマリーが揃っている（前営業日にサマリーがあった銘柄がすべて揃ったか、引けから 12 時間が過ぎた）

**正常フロー**:
1. 日次サマリー生成の終了時、または毎時の定期実行でバッチが起動する
2. 前営業日の確度に、翌営業日 (= 当日) の実績を採点結果として追記する
3. その時点で採点が確定したデータだけから、重み・基準値・中立帯を算出する
4. 当日の各銘柄の軸の値と確度、市場ごとの確度を算出して記録する。予測時点の値として記録し、後から書き換えない

**代替フロー**: 打ち切りで欠けた銘柄は、その日の確度なしで確定する

**例外フロー**:
- 確度の算出や採点に失敗しても、日次サマリーの保存と表示は継続する
- 翌営業日の足が観測カレンダーの次の日付と一致しない銘柄（データ欠落・売買停止をまたぐ）と、翌営業日の |リターン| が 20% を超える銘柄（株式分割をまたぐ等）は採点しない

**スコープ**:
- 稼働開始時は、既存の日次サマリーの履歴から、確度・採点・重みをさかのぼって算出する（既存データは読むだけで書き換えない）。判断軸を追加したときも、同じ方法で過去の成績を算出できる

#### UC-012: 判断軸の成績閲覧

**概要**: ユーザーが判断軸の成績画面で、全軸の成績と、合成した確度の成績（確率帯ごとの実績）を問いごとに確認する

**アクター**: ログインユーザー（`stocks:read` 権限保持者）

**前提条件**: 既存認証フローでログイン済み

**正常フロー**:
1. ユーザーが判断軸の成績画面を開く
2. 問い（方向・荒れ・市場の荒れ）、期間（30 日 / 90 日 / 全期間）、市場（全体 / JP / US）を選ぶ
3. 確率帯ごとの件数・予測の平均・実際の的中率と、軸ごとの件数・的中率・ふだんとの差・現在の重みが表示される

**代替フロー**: 採点済みの予測がない期間は、空状態メッセージを表示する

#### UC-010: 一時アラート失効処理

**概要**: システムが毎時バッチを実行し、取引終了後に期限切れとなった一時アラートを自動削除する

**アクター**: システム（EventBridge Scheduler）

**前提条件**:
- DynamoDB に一時アラートが存在する

**正常フロー**:
1. バッチが毎時起動し、通知頻度ごとに全件の一時アラートを取得する（ページネーション対応）
2. 各アラートを評価し、期限切れ・取引時間外かを確認する
3. 条件を満たすアラートを DynamoDB から削除する
4. 処理統計をログ出力して正常終了する

**代替フロー**: 対象アラートがなければスキップして正常終了する

**例外フロー**:
- マッピング不能な不正データアイテムを検出した場合、該当アイテムの識別情報（AlertID・UserID）をワーニングとしてログ出力し、処理をスキップして後続アラートの処理を継続する
- 個別アラートの削除に失敗した場合はログ出力してスキップし、後続アラートの処理を継続する

**スコープ**:
- 不正なサブスクリプションデータを持つアイテムが存在しても、バッチ全体は停止しない
- ログに個人情報（サブスクリプションの endpoint 等）を含めない

#### UC-009: チャート画面統合表示

**概要**: ユーザーが取引所・ティッカーを選択すると、チャートに加えてサマリー・保有株式・アラート情報をチャート画面上に表示する。サマリーパネルには確度の要約（基準日・方向と荒れの確度・点灯数・更新時間）を表示し、詳細ダイアログボタンから確度の詳細を参照できる。保有株式パネルおよびアラートパネルからは、トップ画面上で直接 CRUD 操作が可能。

**アクター**: ログインユーザー

**前提条件**:
- ユーザーがログイン済み
- 取引所・ティッカーが選択済み

**正常フロー**:
1. ユーザーが取引所とティッカーを選択する
2. システムがサマリー・保有株式・アラート情報を並行取得する
3. サマリーパネルに確度の要約を表示する。詳細ダイアログボタンをクリックすると詳細ダイアログが開く
4. 保有株式情報およびアラート一覧をチャート画面に表示する
5. 保有平均価格ラインとアラートしきい値ラインをチャートにオーバーレイ表示する
6. 保有株式パネル・アラートパネルの追加・編集・削除ボタンから CRUD 操作を行うと、操作完了後にパネルの表示が更新される

**例外フロー**:
- 取引所またはティッカーが未選択の場合、統合情報エリアを表示しない
- 保有なしの場合は「保有なし」を表示し、保有価格ラインは表示しない
- データ取得中はローディング表示し、エラー時はエラーメッセージを表示する

### 2.2 機能一覧

| 機能ID | 機能名                     | 説明                                           |
| ------ | -------------------------- | ---------------------------------------------- |
| F-001  | 株価データ取得             | TradingView API から株価データを取得           |
| F-002  | チャート表示               | ECharts で株価チャートを表示                   |
| F-003  | 取引所管理                 | 取引所の CRUD 操作                             |
| F-004  | ティッカー管理             | ティッカーの CRUD 操作                         |
| F-005  | アラート・通知機能         | 価格条件に基づく通知（Web Push）。通知クリック時は対象チャート画面へ遷移。通知タイトル・通知本文は必須項目で、条件・価格入力時にデフォルト値が自動生成される |
| F-006  | 目標価格算出               | 保有株式の平均取得価格を参照して目標価格を提案  |
| F-007  | 保有株式管理               | 保有株式の CRUD 操作                           |
| F-009  | ユーザー認証               | Auth サービス連携によるログイン・ログアウト    |
| F-010  | 権限管理                   | ロールベースのアクセス制御                      |
| F-011  | 日次サマリー表示           | 取引所ごとのティッカー一覧を表示（シンボル・銘柄名・保有可否・方向と荒れの確度・点灯数・アラート数、`stocks:read` 権限）。確率で並べ替えられる |
| F-012  | 日次サマリー自動生成       | 1 時間間隔バッチで取引時間終了済み取引所の全ティッカーサマリーを自動生成 |
| F-013  | 日足パターン分析           | サマリー更新時に固定パターン分析を実行する。結果は判断軸（単一パターン軸・複合パターン軸）として使う |
| F-014  | 確度の詳細表示             | 詳細ダイアログで、問いごとの確率・ふだんの割合・同じ確率帯の過去実績・軸の内訳（値・過去成績・寄与・件数不足）を表示する |
| F-015  | アラートフィルタリング     | アラート一覧画面で取引所・モードによるクライアントサイドフィルタリングを提供 |
| F-016  | チャート自動更新           | チャート表示中にユーザーが自動更新ボタンをオン/オフし、10秒ごとにデータを再取得する |
| F-017  | チャート画面統合表示       | ティッカー選択時に、サマリー・保有株式・アラート情報をチャート画面上に統合表示する。サマリーパネルは確度の要約（基準日・方向と荒れの確度・点灯数・更新時間）を表示し、詳細ダイアログボタンを提供する。保有株式パネルおよびアラートパネルからトップ画面上での追加・編集・削除が可能。保有平均価格ラインとアラートしきい値ラインをチャートにオーバーレイ表示する |
| F-018  | 一時アラート失効バッチ     | 毎時起動し期限切れの一時アラートを自動削除する。不正データを含むアイテムはスキップして処理継続する。件数上限なく全件取得する（ページネーション対応） |
| F-019  | 判断軸の算出               | 当日までの OHLCV とパターン判定だけから、判断軸（点灯型・数値型）を銘柄 × 日、市場 × 日で算出する |
| F-020  | 確度の算出                 | 問いごとに軸を合成し、確度を確率で出す。ふだんの割合（基準値）・中立帯との比較結果・軸ごとの寄与を、予測時点の値として記録する |
| F-021  | 採点と成績の記録           | 翌営業日の引け後に確度を採点し、軸ごと・確率帯ごとの成績を記録する |
| F-022  | 市場の荒れ予報             | 市場（JP・US）ごとに、翌営業日に市場全体が平常より荒れる確率を表示する。採点済みの日数が少ない間は参考値と明示する |
| F-023  | 判断軸の成績画面           | 全軸の成績と確率帯ごとの実績を、問い・期間・市場を切り替えて表示する（`stocks:read` 権限） |
| F-024  | 成績の初期値算出           | 稼働開始時・判断軸の追加時に、既存の日次サマリーの履歴から成績と重みをさかのぼって算出する |

### 2.3 想定画面の概要

- トップ画面（チャート表示） - `/`：取引所・ティッカー選択、株価チャート・サマリー・保有株式・アラート情報の統合表示
- 保有株式管理画面 - `/holdings`：保有株式の登録・編集・削除
- アラート一覧画面 - `/alerts`：アラートの一覧・作成・編集・削除・絞り込み
- 取引所管理画面 - `/exchanges`（stock-admin のみ）：取引所マスタの管理
- ティッカー管理画面 - `/tickers`（stock-admin のみ）：ティッカーマスタの管理
- サマリー一覧画面 - `/summaries`：市場の荒れ予報、取引所ごとの日次サマリー一覧・確度表示
- 判断軸の成績画面 - `/axis-performance`：判断軸と確度の成績を問い・期間・市場別に可視化

### 2.4 確度の問いと採点

#### 問い

確度は次の 3 つの問いに対して、当日の引け後に出す。答え合わせは翌営業日の引け値で行う（保有期間 1 営業日）。

| 問い | 単位 | 内容 | 確度の意味 |
|---|---|---|---|
| Q-DIR 方向 | 銘柄 × 日 | 翌営業日の終値リターン（当日終値比）が、同じ市場の登録銘柄の同日平均を上回るか | 市場平均を上回る確率 |
| Q-VOL 荒れ | 銘柄 × 日 | 翌営業日の値幅が、その銘柄の平常を上回るか | 平常より荒れる確率 |
| Q-MKT 市場の荒れ | 市場 × 日 | 翌営業日の市場全体（登録銘柄の平均）の値幅が、その市場の平常を上回るか | 市場全体が平常より荒れる確率 |

- 方向を同市場平均との差で測るのは、相場全体の上げ下げ（局面）の影響を除いて、銘柄固有の上乗せだけを評価するためである。市場全体が −2% の日に −1% なら「上回った」になる
- 市場は JP（TSE）と US（NASDAQ・NYSE・AMEX）の 2 つとする（`external-design.md` ADR-010）
- 値幅は (高値 − 安値) ÷ 前営業日の終値、平常は直近 20 営業日（基準日を含む）の値幅の平均とする（`architecture.md` ADR 2.25）

#### 判断軸

判断軸は、当日までの OHLCV（とそこから算出した値）だけを使って機械的に算出できる条件または値とする。軸ごとに、どの問いに使うかを定義として持つ（`architecture.md` ADR 2.26）。

| 区分 | 軸 | 種類 | 問い |
|---|---|---|---|
| 単一パターン | 日足パターン 27 種（買い 11・売り 16）それぞれ | 点灯型 | Q-DIR |
| 複合パターン | 買いパターン合致数 ≥ 2、売りパターン合致数 ≥ 2 | 点灯型 | Q-DIR |
| 値動きの大きさ | 直近 5 日の値幅（Parkinson ボラティリティ）、当日の値幅、出来高比。いずれも平常比 | 数値型 | Q-VOL |
| 市場レベル | 上記の大きさ軸の市場平均、市場平均値幅の平常比 | 数値型 | Q-VOL（大きさ軸の市場平均）・Q-MKT |

- 単一軸の重みづけの合計だけでは「重なったときにだけ出る効果」を表せないため、複合軸を独立した軸として持つ
- 特定のパターン同士のペアは軸にしない。件数が少なすぎるうえ、偶然の当たりを拾いやすいためである
- 判断軸は後から追加でき、追加した軸にも同じ採点・重みづけが適用される

#### 合成の要件

- 重みは、予測日より前に確定した成績だけで決める（ウォークフォワード）
- 件数の少ない軸の重みはゼロに寄せる
- 軸同士の相関を考慮して合成する（単純な多数決や合計にしない）
- 局面によって当たり外れが反転するため、重みは固定せず、直近の成績を反映して更新し続ける
- 確度と一緒に、どの軸も効いていないときの確率（基準値。画面上は「ふだん」）を出し、基準値に近い範囲は「中立」として区別する

具体的な方式は `architecture.md` ADR 2.24〜2.28 を参照。

#### 成績の指標

- 軸ごと・問いごと: 件数（点灯型なら点灯回数）、点灯時の的中率と基準値との差、Q-DIR は点灯時の平均超過リターン
- 合成した確度: 確率帯ごとの件数と実際の的中率（「60% と出したものが実際に 6 割当たっているか」）

## 3. 非機能要件

### 3.1 パフォーマンス要件

| 項目                   | 要件                                    |
| ---------------------- | --------------------------------------- |
| チャート表示           | 初回ロード 2秒以内                      |
| 株価データ取得         | 1秒以内                                 |
| 通知遅延               | 条件達成から 1分以内                    |
| 同時接続数             | 想定 100ユーザー                       |
| アラート設定入力       | 通知テキスト入力時にアラート設定モーダルの不要な再描画が発生しないこと（通知編集は別ダイアログで独立して管理する） |

### 3.2 セキュリティ要件

**認証・認可**:
- Auth サービス（プラットフォーム共通）による JWT 認証
- ロールベースアクセス制御（RBAC）

**Stock Tracker 用のロール定義**:

| ロール名       | 権限（Permissions）                                                                   | 想定ユーザー                |
| -------------- | ------------------------------------------------------------------------------------- | --------------------------- |
| `stock-viewer` | `stocks:read`                                                                         | ゲストユーザー（デフォルト） |
| `stock-user`   | `stocks:read`, `stocks:write-own`                                                     | 一般ユーザー                 |
| `stock-admin`  | `stocks:read`, `stocks:write-own`, `stocks:manage-data`                               | 管理者                       |

**Permission 定義**:

| Permission                  | 説明                                                                 |
| --------------------------- | -------------------------------------------------------------------- |
| `stocks:read`               | チャート閲覧、取引所一覧取得、ティッカー一覧取得、日次サマリー・確度・判断軸の成績の閲覧 |
| `stocks:write-own`          | 自分のアラート設定・保有株式管理                                      |
| `stocks:manage-data`        | 取引所・ティッカーの CRUD（マスタデータ管理）                         |

**データ保護**:
- HTTPS 通信の強制
- DynamoDB のデータは保存時暗号化
- Web Push サブスクリプション情報の暗号化

**セキュリティ対策**:
- XSS 対策: React の自動エスケープ、CSP ヘッダー
- CSRF 対策: SameSite Cookie
- 入力バリデーション: クライアント・サーバー両方で実施
- 機密情報管理: 外部 API キー（Finnhub 等）は Secrets Manager で管理し、実行環境へ安全に注入する

### 3.3 可用性要件

| 項目               | 要件                           |
| ------------------ | ------------------------------ |
| 稼働率             | 99.5%（ベストエフォート）      |
| RTO (復旧目標時間) | 4時間以内                      |
| RPO (復旧目標時点) | 1時間以内（DynamoDB PITR有効） |

**バックアップ戦略**:
- DynamoDB Point-in-Time Recovery (PITR) 有効化
- 保持期間: 35日間

### 3.4 保守性・拡張性要件

**コード品質**:
- TypeScript strict mode 有効
- ESLint による静的解析
- テストカバレッジ 80%以上（ビジネスロジック）

**モジュール化**:
- core パッケージ: ビジネスロジック（フレームワーク非依存）
- web パッケージ: Next.js UI
- batch パッケージ: Lambda 関数（通知バッチ）

**拡張ポイント**:
- 新しい条件タイプの追加（パターン認識など）
- 判断軸の追加（テクニカル指標など）
- 新しいチャートライブラリへの切り替え
- 複数の株価データソースへの対応

### 3.5 その他の非機能要件

**スケーラビリティ**:
- Lambda 自動スケール（Web）
- DynamoDB オンデマンドキャパシティ
- EventBridge Scheduler による定期実行（バッチ）

**インフラ**:
- **Web**: Lambda (Web Adapter) + CloudFront
- **Batch**: Lambda + EventBridge Scheduler
- **データストア**: DynamoDB
- **認証**: Auth サービス（本プラットフォーム共通）

**モニタリング**:
- CloudWatch Logs による統一ログ管理
- CloudWatch Alarms によるエラー監視

**障害分離**:
- 確度の算出や採点に失敗しても、日次サマリー（OHLCV・パターン判定）の保存と表示は継続する

**確度の算出**:
- 算出タイミング: 確度は日次サマリー生成と同じタイミング（取引所の引け後）で出す
- 再現性: 同じ入力データからは、同じ軸の値・重み・確度が得られる（乱数を使わない）
- 将来データの混入防止: 重みの算出と成績の初期値算出が、予測時点で確定していないデータを使わないことを、テストで検証できる形にする
- 外部 AI への依存なし: OpenAI など外部 AI サービスを呼ばない
- 拡張の容易さ: 判断軸の追加で、既存レコードの移行やデータ構造の作り直しを必要としない。既存レコードに新しい軸の値がなくても、表示・集計が壊れない

## 4. ドメインオブジェクト

| エンティティ | 説明 |
| ----------- | ---- |
| Exchange（取引所） | 株式が取引される市場（例: NYSE, NASDAQ） |
| Ticker（ティッカー） | 個別銘柄を識別するシンボル |
| Holding（保有株式） | ユーザーが保有する銘柄・数量・平均取得価格 |
| Alert（アラート） | 価格条件に基づく通知設定 |
| PushSubscription | Web Push 通知の購読情報 |
| DailySummary（日次サマリー） | ティッカーごとの、その日の足（OHLCV）と、足から決まる判定（パターン分析） |
| 問い（Question） | 確度を出す対象。Q-DIR（方向）・Q-VOL（荒れ）・Q-MKT（市場の荒れ） |
| 判断軸（Axis） | 機械的に算出できる条件または値。単一パターン軸・複合パターン軸・値動きの大きさ軸・市場レベルの軸がある |
| 確度（Forecast / MarketForecast） | 問いごと・銘柄（または市場）× 日の確率と基準値、軸の値と寄与。予測時点の値として残し、翌営業日に採点結果を付ける |
| 重み（ModelSnapshot） | 問いごとに、予測日より前の成績から決まる合成時の重みと、基準値・中立帯・軸ごとの成績 |

## 5. スコープ外

- ❌ テクニカル指標（移動平均、ボリンジャーバンド、RSI など）。判断軸として後から追加できる仕組みだけを持つ
- ❌ 特定のパターン同士のペアを判断軸にすること
- ❌ 予測タイミングの変更（米国市場の引け後に翌日の東証を予測する等）
- ❌ サポートレベル・レジスタンスレベル（AI の出力だったため撤去した。機械的な代替は持たない）
- ❌ 確度にもとづく通知（アラート）
- ❌ ポートフォリオ分析機能
- ❌ 複数の株価データソース対応
- ❌ カスタムアラート条件（JavaScript ベースのカスタム条件式）
- ❌ バックテスト機能
- ❌ AI による解析・予測

| 用語 | 説明 |
