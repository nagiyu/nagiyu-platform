# アラート

利用者が、価格条件を決めてアラートを作り、条件を満たしたときに Web Push の通知を受け取る。通知から、その銘柄のチャートへ移れる。一時通知のアラートは、期限を過ぎると失効する。ユースケースは[アラートを設定する](../use-cases/set-alert.md)、[アラートを絞り込む](../use-cases/filter-alerts.md)、[通知を受けて銘柄を開く](../use-cases/receive-alert.md)。

## 要件

### 条件と設定

- 価格条件を、買い・売りのモードで設定できる。条件は、単一の価格 (以上・以下) か、範囲 (範囲内・範囲外) ([アラート API](../../specs/api/alerts.md))
- 判定の頻度を、1 分間隔と 1 時間間隔から選べる
- 任意のカスタムメッセージを付けられる
- アラートの有効・無効の切り替え、条件の編集、削除ができる。作ったあとは、モードと頻度を変えられない
- 一覧で、取引所とモードで絞り込める。絞り込みの状態は URL に反映しない ([アラート一覧画面](../../specs/screen/alerts.md))
- アラートは、利用者ごとに分かれる ([アクセス制御](access-control.md))

### 判定と通知

- 取引所が取引時間内のアラートだけを判定する ([取引時間](../../specs/term/trading-hours.md))。現在価格は、取引所の設定に従って取る ([価格の取得元](../../specs/term/price-source.md))
- 1 分間隔のアラートは毎分、1 時間間隔のアラートは毎時 1 回だけ判定する ([分次バッチ](../../specs/batch/minute.md)、[時間次バッチ](../../specs/batch/hourly.md))
- 条件を満たすと、アラートが持つ購読へ Web Push で通知する。条件を満たしている間は、判定のたびに通知する。通知したあとも、アラートは有効のまま変わらない
- 通知の文面は固定で、利用者が決められるのは任意のカスタムメッセージだけ。カスタムメッセージは、本文の末尾に付く ([アラート通知の経路](../../specs/flow/alert-notification.md))
- 通知から、通知元の取引所とティッカーを選んだチャート画面を開ける
- アラートの判定は、分次・時間次のバッチだけが行う。日次バッチは、保存された購読の形を点検してログに出すだけで、アラートを判定しない ([日次バッチ](../../specs/batch/daily.md))
- 通知を許可済みなら、画面を開くたびに、利用者のアラートの購読が、開いた端末のものに更新される ([Push 通知 API](../../specs/api/push.md))

### 一時通知の失効

- アラートを一時通知にできる。一時通知は、期限の取引日を過ぎると失効する ([一時通知](../../specs/term/temporary-alert.md))
- システムが毎時、期限を過ぎた一時通知を無効にして、自動削除の対象にする。物理的な削除は、DynamoDB の TTL に任せる ([一時通知アラート失効バッチ](../../specs/batch/temporary-alert-expiry.md))
- 失効させるのは、取引所が取引時間外のときに、最新取引日が期限の取引日以降になっているアラート。取引時間内のアラートには触れない。利用者が無効にした一時通知は、期限を待たず、取引時間外になった回に自動削除の対象にする
- 対象のアラートは、頻度ごとに最大 20 ページ (1 ページ 50 件) を読む。超えたら警告ログを出して、読めた分で処理する。件数に上限なく全件を読むわけではない
- 不正な購読データを持つアラートがあっても、バッチ全体は止めない。個別のアラートの処理に失敗しても、後続のアラートの処理を続ける ([信頼性](../non-functional/reliability.md))

## やらないこと

- **無効な購読の自動削除**: 購読はアラートの一部で、消すと利用者の条件設定ごと失われるため。購読は、利用者が画面を開くと更新される
- **祝日を考慮した一時通知の期限**: 祝日マスターを持たないため ([日次サマリー](daily-summary.md))。期限の取引日が祝日に当たると、実質 1 取引日短くなる
