# ユースケースの名前

必須。誰が何のために何をするかを 1〜2 文で書く。見出しは付けない。ユースケースは 1 件につき 1 本置く。要件は出典を持たない (`sources: []`)。

> この雛形は `docs/services/<service>/requirements/use-cases/<name>.md` に写して使う。説明の文を消し、本文に置き換える。

## 前提

必須。始める時点で成り立っていること (ログイン済み、データがあるなど)。

## 流れ

必須。利用者の操作とサービスの応答を、順に番号付きで書く。画面の中身や API は書かず、仕様にリンクする。

## 結果

必須。終わった時点で成り立っていること。

## 例外

任意。流れが別の道に分かれる場合 (権限がない、入力が誤っているなど) を書く。
