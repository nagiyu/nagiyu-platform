# テーマの名前

必須。何についての要件か (性能、可用性、セキュリティ、運用など) と、対象の範囲を 1〜2 文で書く。見出しは付けない。非機能要件はテーマ 1 つにつき 1 本置く。全サービス共通の水準は、ここに書かず規約 (`platform/rules/`) に書く。要件は出典を持たない (`sources: []`)。

> この雛形は `docs/services/<service>/requirements/non-functional/<name>.md` に写して使う。説明の文を消し、本文に置き換える。

## 要求水準

必須。満たすべき水準を、測れる形 (数値・条件) で書く。共通の水準と違う点があれば、その違いと理由を書く。

## やらないこと

必須。水準を求めない範囲と、その理由を書く。
