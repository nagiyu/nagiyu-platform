# サービス名

必須。このサービスが何で、誰のために何を解決するかを 1〜2 文で書く。見出しは付けない。目的はサービスに 1 本置く。要件は出典を持たない (`sources: []`)。

> この雛形は `docs/services/<service>/requirements/purpose.md` に写して使う。説明の文を消し、本文に置き換える。

## 解決したい課題

必須。利用者が困っていること、サービスがなければどうなるかを書く。

## 扱わない範囲

必須。サービスとして扱わない範囲を、理由を添えて書く。やらないと決めたことは、ここと機能要件の「やらないこと」に残す。

## 利用者

任意。想定する利用者が複数あり、立場で扱いが変わるときに書く。
