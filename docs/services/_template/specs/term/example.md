# 用語の名前

必須。用語の一言の定義。見出しは付けない。用語は 1 つにつき 1 本置く。廃止した用語の文書は作らない (昔の中身は git の履歴にある)。

> この雛形は `docs/services/<service>/specs/term/<name>.md` に写して使う。説明の文を消し、本文に置き換える。

## 説明

必須。数行で、値の種類・使われ方・ほかの概念との関係を書く。関連する仕様へは本文でリンクする。

## 理由

任意。この仕様になっている理由を、今の状態として現在形で書く。採らない案とその理由、判断の根拠になった実測値を含める。時系列の経緯と、置き換えられた決定は書かない。

## 手順

任意。この仕様が触る対象を操作する・確かめる手順 (切り替え、復旧、手動実行、手元でしか流せないテストの流し方など) を書く。手順は独立した文書にせず、対象の仕様に書く。
