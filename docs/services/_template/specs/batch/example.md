# バッチの名前

必須。バッチが何をするかを 1〜2 文で書く。見出しは付けない。バッチは定期実行されるもの 1 つにつき 1 本置く。

> この雛形は `docs/services/<service>/specs/batch/<name>.md` に写して使う。説明の文を消し、本文に置き換える。

## 起点

必須。スケジュール、または起動のきっかけ。利用者の操作などで 1 件ずつ起動するジョブは、何が起動するかを書く。

## 対象から外れる条件

任意。`## 起点` の次に置く。対象になる条件 (最低発話数・見る期間など) もここに書く。

## 処理

必須。フロー図 (mermaid) + 表・箇条書き。順番・分岐・止まる条件を図に描き、細かい条件と数値は図の下に置く。図の書き方は [経路の雛形](../flow/example.md) の「図の書き方」に従う。

## 上限

任意。`## 処理` の次に置く。処理を止める仕組みとしての上限 (回数・件数の上限など) だけを書く。処理のパラメータ (候補の上位件数・保持件数・文字数など) は、処理の表・箇条書きに書く。

## 失敗したとき

必須。失敗時の扱い (再実行・通知・取りこぼしなど)。

## つながり

必須。起点・読み書きするデータ・ほかのバッチや Admin との関係を図 (mermaid) で描く。処理の中身は描かない。

## 理由

任意。この仕様になっている理由を、今の状態として現在形で書く。採らない案とその理由、判断の根拠になった実測値を含める。時系列の経緯と、置き換えられた決定は書かない。

## 手順

任意。この仕様が触る対象を操作する手順 (切り替え、復旧、手動実行など) を書く。手順は独立した文書にせず、対象の仕様に書く。
