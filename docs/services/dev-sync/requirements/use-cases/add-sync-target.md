# 同期の対象を足す

開発者が、サービスのデータを dev-sync の対象に足し、prod のデータを dev で使えるようにする。

## 前提

- 足したいデータが、DynamoDB のテーブルにある
- データの出自の分類で、prod から写すべきクラスに当たる ([dev 環境のデータ](../../../../platform/rules/dev-data.md))

## 流れ

1. 開発者が、データの出自の分類で、写すべきデータかを判断する。外部 API 由来・コード / 設定由来・派生のデータと、dev で自分で作る個人データは写さない
2. 開発者が、戦略を選ぶ。prod の削除を dev に映す必要があるかで決める ([同期戦略](../../specs/term/sync-strategy.md))
3. 開発者が、マニフェストにジョブを足す ([同期バッチ](../../specs/batch/sync.md))
4. 新しいコピー元のテーブルのときは、prod の読み取りロールが読めるテーブルの一覧にも足して、prod へリリースする ([prod 読み取りロール](../../../../platform/specs/resource/dev-sync-source-reader.md))
5. dev へデプロイする

## 結果

- 足したデータが、定期の同期で dev に写る ([同期](../functional/sync.md))

## 例外

- 新しいコピー元のテーブルを、読み取りロールの一覧に足して prod へリリースするまでは、そのジョブは権限エラーで失敗し、Admin に通知が届く
- コピー先が dev のテーブルでないときは、ジョブを足せない ([セキュリティ](../non-functional/security.md))
