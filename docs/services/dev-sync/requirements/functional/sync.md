# 同期

prod が正のデータ ([dev 環境のデータ](../../../../platform/rules/dev-data.md)の分類のうち、写すクラス) を、定期に dev へ写す。prod で削除したものも dev に映し、何回・いつ流しても同じ結果にする。

## 要件

- 同期の対象を、マニフェストのジョブとして宣言できる ([同期バッチ](../../specs/batch/sync.md))
- ジョブを、定期に実行できる。手動でも実行できる
- prod の削除を dev に映せる。削除を反映する対象では、コピー元の対象範囲を全件写し、prod に無い dev のアイテムを消す ([同期戦略](../../specs/term/sync-strategy.md))
- 何回・いつ流しても同じ結果になる。定期の実行と手動の実行のどちらも同じである
- dev で同期の対象を書き換えても、次の同期で prod の内容に戻る (後勝ち)
- 同期が失敗したときは、Admin に通知される ([エラーの収集](../../../admin/requirements/functional/error-collection.md))
- サービスのデータを足すときは、マニフェストへの追加で済む ([同期の対象を足す](../use-cases/add-sync-target.md))

## やらないこと

- **dev で独立に運用したい個人データ (保有・アラート・ユーザー設定など) は写さない**: 理由は [dev 環境のデータ](../../../../platform/rules/dev-data.md)にある
- **prod へ書かない、dev から prod へ逆向きに写さない**: 同期は prod を読むだけにする。dev のデータは prod の正にならない ([目的](../purpose.md)、[セキュリティ](../non-functional/security.md))
- **対象範囲に入らないアイテムは触らない**: 写さず、dev から消しもしない。同じテーブルには、写さない個人データも入っている。範囲の外まで消すと、dev で自分で作ったものが消える。同じテーブルの別の範囲を写すときは、別のジョブにする
