# 申し込みと管理

利用者が、自分で有料プランに申し込み、解約や支払い方法の変更などの契約の管理を行えるようにする。ユースケースは[有料プランに申し込む](../use-cases/subscribe.md)と[契約を管理する](../use-cases/manage-subscription.md)。

## 要件

- ログイン中の利用者が、Stripe の決済画面 (Checkout) で有料プランに申し込める。決済の入力は Stripe の画面で行い、Auth はカード情報を受け取らない ([プラン画面](../../specs/screen/plans.md)、[課金 API](../../specs/api/billing.md))
- 支払いを終えて戻ったときに、Stripe から契約を取り直して課金の権利に反映し、ロールを再取得してから、元のサービスへ戻る。この時点で有料ロールが有効になっている ([契約がロールになる経路](../../specs/flow/billing-entitlement.md))
- 決済画面で中止したときは、何も変わらずプランの画面へ戻る
- 未ログインのときは、ログインへ案内する
- 同じサービスの有効な契約があるときは、別の段でも新たに申し込ませず、プランの画面の段の切り替えへ案内する ([段の切り替え](plan-change.md))
- 課金が有効になっていないときは、価格と操作の代わりに「準備中」を示す。表記へのリンクは準備中でも出す
- 本番以外では、`billing:test` 権限を持つ `billing-tester` ロールを持たない利用者 (未ログインを含む) は、申し込めない。画面は導線を出さずにその旨を示し、申し込みの API も断る。dev の Stripe のサンドボックスは、テスト用のカードで支払いが通るため、誰でも無料のまま有料の段を得られてしまうのを防ぐ。制限は新規の申し込みだけにかけ、契約の管理・段の切り替え・予約の取り消し・Stripe との同期は変えない ([ロールと権限](../../../../platform/specs/lib/common/roles-and-permissions.md))
- 契約中の利用者が、Stripe の Customer Portal で、解約・支払い方法の変更・請求の確認を行える。解約した場合も、支払い済みの期間の終わりまでは、有料ロールが有効なままになる
- Stripe の顧客と対応していない利用者には、「契約を管理」を出さない
- 申し込みと契約の管理は、ログイン中の本人の分だけを扱う ([セキュリティ](../non-functional/security.md))

## やらないこと

- **解約・支払い方法の変更・請求の履歴の画面を自作すること**: Stripe の Customer Portal に任せる。作る量を減らし、カード情報を Auth で扱わないため
- **同じサービスの契約が 2 件にならないようにすること**: 2 つのタブで決済画面を開き、両方で支払った場合に限り、同じプランの契約が 2 件できる。現実的に起きないものとして許容する
- **販売代行型 (Merchant of Record) を使うこと**: 税の処理を代行する代わりに、追加の手数料がかかる (Stripe Managed Payments で +3.5%)。当面は国内の顧客が中心で、消費税は免税事業者の範囲に収まるため、手数料に見合う利点がない。日本の売り手の国内取引は、Stripe Managed Payments の税務代行の対象外でもある。このため、海外の顧客向けの税の処理も扱わない
- **カード以外の定期課金**: 定期課金で使えるのはカード (Apple Pay / Google Pay を含む) に限られ、PayPay とコンビニ決済は定期課金に使えないため
- **返金の仕組みを持つこと**: 返金は Stripe の管理画面から手で行う ([Stripe](../../specs/resource/stripe.md))
- **dev 環境そのもののアクセス制限**: 制限するのは新規の申し込みだけで、dev へのログインは止めない
