# 課金の反映

Stripe 上の契約の変化を、利用者の操作なしに課金の権利へ反映し、最終的に Stripe の状態と一致させる。

## 要件

- Stripe からの通知は、署名を検証してから処理する。署名を検証できない通知は処理しない ([Stripe 通知 API](../../specs/api/billing-webhook.md))
- 通知は「その顧客の何かが変わった」という合図としてだけ使い、毎回、その顧客の最新の契約を Stripe から取り直して、Stripe 由来の課金の権利を書き換える。順序の入れ替わりや重複があっても、Stripe の状態と食い違わないようにするため
- 通知が遅れる・重複する・順序が入れ替わる・取りこぼされるときも、最終的には Stripe 上の最新の状態に一致する
- 通知の顧客が Auth のユーザーと結びつかないときは、何もせず成功を返す。再送されても結果が同じため
- 書き換えに失敗したときは、失敗を返し、Stripe に再送させる
- 決済を終えて戻った利用者は、プランの画面で同期してから、ロールの再取得へ送り、元のサービスへ戻ったときには反映されている ([契約がロールになる経路](../../specs/flow/billing-entitlement.md))
- ログイン中の利用者がプランの画面を開いたときにも、Stripe から取り直して同期する。更新の通知を取りこぼすと、払っている利用者の権利が期限で切れうるため

## やらないこと

- **期限を JWT に載せて、期限切れ・解約を読む側で即時に外すこと**: 期限切れの判定は、Auth が有効なロールを決めるときにだけ行う。解約した人や期限が切れた人が、Auth を通るまで、最長でセッションの期限まで有料ロールを持ち続けうるが、許容する。詳しい理由は[セッションのロール](../../specs/term/session-roles.md)の理由にある
