# 課金の権利の管理

管理者が、課金の権利を手動で付け、期限を変え、取り消せるようにする。ユースケースは[有料ロールを手動で付ける](../use-cases/grant-paid-role.md)と[Stripe の顧客との対応を外す](../use-cases/unlink-stripe-customer.md)。

## 要件

- `roles:assign` 権限を持つ管理者が、付ける有料ロールと有効期限を指定して、課金の権利を足せる ([ユーザー編集画面](../../specs/screen/user-edit.md)、[課金の権利](../../specs/term/role-grant.md))
- 手動で付けた権利の期限を変えられ、取り消せる。期限の変更は、新しい期限が現在より後なら、延長・短縮・期限切れからの復活のいずれも許す。日付の入れ間違いを直せるようにし、支援を再開した人を同じ権利で扱えるようにするため
- 取り消した権利は変更できない。新しい期限が現在より前のときは、エラーにする
- 権利の変更は、手動ロールの変更と一緒にまとめて保存する。他の更新と競合したときは、再読み込みを促す ([ユーザー API](../../specs/api/users.md))
- Stripe 由来の権利は、表示だけで、手では変えられない。Stripe 上の契約と食い違わないようにするため
- 課金の権利として付けられるのは、有料ロールだけにする。課金の権利は、有料ロールを手動ロールと分けて扱うための仕組みであるため
- 手動ロールには、有料ロールを入れさせない。手動ロールに入れると期限なしで有効になり、課金の権利の期限と出どころの管理をすり抜けるため。課金を通さずに有料の段を付けるときも、出どころが手動で期限つきの権利として付ける
- Stripe の顧客との対応を外せる。外すと、同じ書き込みで、Stripe 由来の有効な権利も取り消す。対応が外れると、この先の通知で権利を書き換えられなくなるため。Stripe 上の顧客と契約には触れない。対応がないユーザーには、エラーにする

## やらないこと

なし
