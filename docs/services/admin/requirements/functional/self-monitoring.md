# 自己監視

エラーを集めて通知する仕組み自身が壊れたときも、本流とは独立した経路で、管理者に Push が届くようにする。

## 要件

- 通知の仕組み自身の障害を検知し、本流とは別の経路で管理者に Push で知らせる ([エラー通知の経路](../../specs/flow/error-notification.md)、[自己監視](../../specs/resource/self-monitoring.md))
- 本流が止まっていても届く。本流が止まったときに、通知も一緒に止まってしまわないようにするため
- 自己監視の通知は、エラーの履歴には残さない。履歴に残すには、監視している本流の保存先を使うことになり、同じ障害で記録できなくなるため
- 自己監視の通知は、タップするとダッシュボードが開く。履歴に詳細がないため ([SNS 受信 API](../../specs/api/notify-sns.md))
- 自己監視の通知は、通知を購読している端末すべてに送る

## やらないこと

- **自己監視の失敗の、履歴への報告**: 監視される側の仕組みに頼ってしまうため
