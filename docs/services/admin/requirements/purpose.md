# admin

nagiyu プラットフォームの運用者 (`admin` ロールの管理者) が、全サービスの失敗に気づき、その中身を確かめるための窓口。エラーの履歴と Push 通知で、運用者に失敗を届ける。

## 解決したい課題

サービスの失敗は、各サービスのログやアラームの中に散らばる。運用者は、失敗が起きたこと自体に気づけず、気づいても中身を確かめるまでにサービスごとの場所を探し回ることになる。

このサービスは、各サービスの失敗を 1 か所に集めて履歴に残し、記録されたら運用者の端末へ Push 通知で知らせる。運用者は通知から、そのエラーの内容を直接開ける。ログインは Auth の SSO に任せ、Admin は専用のログインを持たない ([サインイン](functional/sign-in.md))。

## 扱わない範囲

- **ユーザーとロールの管理**: Auth が持つ。Admin は、ログインした利用者のロールから権限を判定するだけで、ロールを付け外しする画面を持たない ([ユーザー管理](../../auth/requirements/functional/user-management.md))
- **同じ失敗の重複の除去**: 取りこぼすより、同じ失敗の通知が 2 通届くほうが安全なため ([エラーの収集](functional/error-collection.md))

## 利用者

- **運用者**: `admin` ロールを持つ管理者。エラーの履歴を見て、Push 通知を受け取る
