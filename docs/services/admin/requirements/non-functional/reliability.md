# 信頼性

失敗を黙って失わないための水準。エラーの収集と通知の経路を対象にする。

## 要求水準

- アプリが報告できない失敗も、取りこぼさない。タイムアウトなどでプロセスが即死した失敗は、CloudWatch Alarm と AWS Batch のジョブ失敗の経路が拾う ([エラーの収集](../functional/error-collection.md))
- エラーの記録の保存は、通知の成否に依存しない。通知は記録のあとに送り、通知の失敗は記録に影響しない ([Push 通知](../functional/push-notification.md))
- 同じ失敗が重複して記録され、通知が重なって届くことは許す ([目的](../purpose.md)の「扱わない範囲」)
- 通知の仕組み自身の障害にも気づける。本流とは独立した経路で、運用者に Push が届く ([自己監視](../functional/self-monitoring.md))
- アプリの報告の保存に失敗しても、報告したアプリの本来の処理は止めない ([エラーの収集](../functional/error-collection.md))

## やらないこと

- **稼働率や通知の到達時間の数値の目標**: 測る仕組みを持たず、根拠のある水準を置けないため
