# さくっとクリップ (QuickClip) 要件定義書

この文書は、何を満たすべきか (目的・対象利用者・要件・非機能の目標) を書く。今どう動くかは[仕様カード](../../specs/README.md)にあり、各節からリンクする。

---

## 1. ビジネス要件

### 1.1 背景・目的

**背景**:

- 動画投稿者が長時間の動画から「見どころ」を探す作業は手間がかかり、時間を要する
- 動画の変化量・音量などの客観的指標を用いて、見どころを機械的に抽出することで、この作業を自動化・効率化したい

**目的**:

- 動画をアップロードするだけで、見どころ候補を自動抽出するサービスを提供する
- ユーザーが抽出された見どころを確認・選別・調整し、最終的に分割クリップとして書き出せるようにする

### 1.2 対象ユーザー

**プライマリーユーザー**:

- 動画投稿者（YouTuber・ニコニコ動画投稿者など）
- 長時間動画から切り抜き・ハイライト動画を作成したい

ログインは任意。ログインしなくても使えるが、ログインや有料プラン (スタンダードとプロの 2 段) で使える量が増える。

### 1.3 ビジネスゴール

1. **見どころ抽出の自動化**: 動画の変化量・音量の大きさを分析し、見どころを自動特定する
2. **確認・選別の効率化**: 抽出された見どころをWeb画面上でプレビューしながら採否判定・時間調整できる
3. **書き出しの簡便化**: 採用した見どころを分割クリップのZIPとしてダウンロードできる
4. **意味的な見どころ抽出**: 文字起こしと感情分析 ([AI 解析](../../specs/quick-clip/term/ai-analysis.md)) による見どころ抽出を、映像・音量の抽出に加える

## 2. 機能要件

### 2.1 ユースケース

各ユースケースの今の挙動 (画面の要素、操作、API、バッチの処理手順) は、リンク先の仕様カードを参照する。ここには、何を満たすべきかだけを書く。

#### UC-001: 動画アップロード

**概要**: ユーザーが動画ファイルをアップロードし、見どころ抽出のジョブを作る

**アクター**: 動画投稿者

**前提条件**: なし (ログイン不要。ログインの有無で使える量が変わる)

**満たすべきこと**:

- 非対応の形式、上限を超えるサイズのファイルは、アップロードを始めずに断る
- 動画の長さが段の上限を超える場合、または今月の回数の上限に達している場合も、アップロードを始めずに断る (2.2 の F-022)

**今の挙動**: [アップロード画面](../../specs/quick-clip/screen/upload.md)、[ジョブ API](../../specs/quick-clip/api/jobs.md)、[見どころを受け取るまでの経路](../../specs/quick-clip/flow/extraction.md)

#### UC-002: 見どころ確認・選別

**概要**: 抽出された見どころをWeb画面上でプレビューし、採否の判定と開始・終了時刻の調整をする

**アクター**: 動画投稿者

**前提条件**: UC-001 が完了し、見どころ抽出が完了している

**満たすべきこと**:

- 画面を開いた時点で、全クリップが再生できる
- 開始・終了時刻を調整したら、クリップが自動で作り直される。調整した見どころは、確認済みの採否を未確認に戻す
- 一部の見どころだけを採用した状態でも、ダウンロードに進める

**今の挙動**: [見どころ確認画面](../../specs/quick-clip/screen/highlights.md)、[見どころ API](../../specs/quick-clip/api/highlights.md)、[クリップ再生成](../../specs/quick-clip/batch/clip-regenerate.md)

#### UC-003: 見どころダウンロード

**概要**: 採用した見どころの切り出しクリップをZIPとしてダウンロードする

**アクター**: 動画投稿者

**前提条件**: UC-002 が完了し、1 件以上の見どころが採用されている

**満たすべきこと**:

- 採用したクリップの生成がすべて終わるまで、ダウンロードできない
- 文字起こしがあるクリップには、対応するテキストを同じ ZIP に同梱する

**今の挙動**: [見どころ確認画面](../../specs/quick-clip/screen/highlights.md)、[ダウンロード API](../../specs/quick-clip/api/download.md)、[ZIP 生成](../../specs/quick-clip/batch/zip-generate.md)

#### UC-004: 動画広告の視聴

**概要**: ユーザーが処理中画面で動画広告を視聴する

**アクター**: 動画投稿者

**前提条件**: UC-001 が完了し、処理中画面を表示している

**満たすべきこと**:

- 広告の再生が終わり、かつ処理が完了するまで、見どころ確認へ進むボタンを有効にしない。どちらが先に終わっても同じ
- 広告に関するあらゆる失敗では、広告が終わったものとして扱い、見どころ確認へ進めるようにする (3.6)
- 広告の配信元を設定しない環境では、広告を出さない

**今の挙動**: [処理状況画面](../../specs/quick-clip/screen/job-status.md)

#### UC-005: 感情フィルタ指定付きジョブ作成

**概要**: ジョブ作成時に感情フィルタを指定し、見どころ抽出に感情スコアを加える

**アクター**: 動画投稿者

**前提条件**: [AI 解析](../../specs/quick-clip/term/ai-analysis.md)をするジョブである

**満たすべきこと**:

- 感情フィルタ (`laugh` / `excite` / `touch` / `tension` / `any`) を、ジョブ作成の API で指定できる
- 映像の変化量・音量・感情の 3 つの根拠から、見どころを抽出する
- AI 解析ができない場合 (文字起こしが空、API の失敗など) は、その処理を飛ばし、映像の変化量と音量だけで抽出を続ける。ジョブ全体は失敗にしない

**今の挙動**: [ジョブ API](../../specs/quick-clip/api/jobs.md)、[抽出バッチ](../../specs/quick-clip/batch/extract.md)、[AI 解析](../../specs/quick-clip/term/ai-analysis.md)

### 2.3 利用回数の制限

段は、未ログイン / 無料 (ログイン) / スタンダード / プロ / 使い放題の 5 つ。段ごとの回数と長さの上限は、[利用の段と上限](../../specs/quick-clip/term/usage-tier.md)を参照する。

- 回数は、AI 解析ありとなしを別々に、日本時間の暦月で数える
- 有料プランの金額は Stripe 側で持ち、本書には書かない
- 使い放題は売らず、プランの画面にも出さない。運営者が自分で使うための手動ロールで、回数は数えず、1 本の長さの上限だけを受ける
- 動画をアップロードする前に、AI 解析をするかしないかを選べる。残りの回数がなければ、AI 解析なしを既定にする
- 残りの回数を画面に表示する
- 動画の長さが段の上限を超える場合、または選んだ種類の回数の上限に達している場合は、アップロードを始める前に断る。回数の上限のときは、プランの画面へ案内する
- 処理に失敗したときは、理由を問わず回数を戻す。AI 解析が失敗して AI 解析なしで完了したときは、AI 解析なしの 1 回として数える
- 回数を記録する仕組みが使えないときは、数えずに受け付ける。ただし AI 解析ありの申し込みも、AI 解析なしとして処理する
- 値の根拠は [ADR-018](./architecture.md) を参照する

数え方と戻し方の今の挙動は[利用回数の流れ](../../specs/quick-clip/flow/usage-metering.md)、残りの返し方は[利用状況 API](../../specs/quick-clip/api/usage.md)を参照する。

## 3. 非機能要件

### 3.1 パフォーマンス要件

| 項目 | 要件 |
| ---- | ---- |
| 見どころ抽出処理時間 | 30秒以内（目安）。感情分析有効時は +60 秒以内の増加を許容する（文字起こし + 感情分析 API 呼び出しのオーバーヘッド） |
| 同時処理ジョブ数 | 最大3ジョブ（1ユーザーにつき1ジョブまで、同時3ユーザー想定） |
| ZIPダウンロード生成時間 | 30秒以内（目安）※ 難しければ多少の超過は許容 |
| アップロード上限 | 20 GB まで受け付けること |
| Batch 対応ファイルサイズ | 20 GB までの動画を OOM なく処理できること |
| Batch リソース選択 | ファイルサイズと動画の長さに応じて、自動的に適切な Batch Job Definition を選択すること。選び方と各サイズの値は[Batch ジョブ定義のサイズ](../../specs/quick-clip/term/job-definition-size.md)を参照する |

### 3.2 セキュリティ要件

- **データ暗号化**:
    - 転送時: HTTPS（すべての通信）
    - 保存時: S3 SSE-S3（サーバー側暗号化）
- **アクセス制御**:
    - S3バケット: 非公開（Presigned URLのみでアクセス）
    - ジョブアクセス: ジョブIDのみで制御。ジョブIDを知れば誰でも確認できるが、ジョブIDを UUID v4 等の推測困難な文字列にすることでリスクを軽減する
- **ウイルススキャン**: 実施しない

### 3.3 可用性要件

AWS サービスの可用性に依存する。個別の稼働率・RTO・RPO 目標は設定しない（ベストエフォート）。

### 3.4 保守性・拡張性要件

- 新しい AI 機能の追加を考慮した拡張可能なアーキテクチャとする
- 見どころ抽出アルゴリズムを差し替え・追加しやすいモジュール構成とする

### 3.5 その他の非機能要件

- **ファイル保持期間**: アップロードファイル・生成クリップ・文字起こし・ZIP ともに1日で自動削除する。ジョブと見どころのレコードも、同じ期限で自動削除する ([ジョブとステータス](../../specs/quick-clip/term/job.md)、[見どころとクリップの状態](../../specs/quick-clip/term/highlight.md))
- **対応ブラウザ**: Chrome・Edge（最新版）
- **対応デバイス**: PC（デスクトップ）のみ。スマートフォン対応・PWA 対応は行わない（codec-converter と同方針）

### 3.6 広告に関するエラー耐性

- 広告に関するあらゆるエラー（SDK ロード失敗・no fill・再生エラー・広告ブロッカー）は、**ユーザー体験を損なわないようフォールバック**し、広告が終わったものとして見どころ確認へ進めるようにしなければならない
- 広告エラーをもってサービス全体の利用を妨げてはならない
- CI・E2E テスト環境では広告の配信元を設定せず、広告処理をスキップする

## 4. ドメインオブジェクト

| エンティティ | 説明 |
| ----------- | ---- |
| Job（ジョブ） | 動画のアップロードと見どころ抽出処理を管理する単位。詳細は[ジョブとステータス](../../specs/quick-clip/term/job.md) |
| Highlight（見どころ） | 動画内の特定区間。採否、クリップの状態、抽出根拠を持つ。詳細は[見どころとクリップの状態](../../specs/quick-clip/term/highlight.md) |
| UploadedVideo（アップロード動画） | ユーザーがアップロードした元動画ファイル |
| Clip（クリップ） | 採用された見どころから生成される分割動画ファイル |
| EmotionScore（感情スコア） | 動画内セグメント単位で算出された感情カテゴリ別スコア（laugh / excite / touch / tension: 各 0.0〜1.0） |
| EmotionLabel（感情ラベル） | 感情カテゴリの識別子（laugh / excite / touch / tension） |
| EmotionFilter（感情フィルタ） | 見どころ抽出で使用する感情カテゴリの指定（laugh / excite / touch / tension / any） |

## 5. スコープ外

- ❌ 複数動画の同時アップロード
- ❌ 感情フィルタ選択 UI（フロントエンドの選択 UI は実装しない。API パラメータの受け口のみ）
- ❌ パート分割機能（将来実装予定）
- ❌ 感情スコア配列の永続化（抽出済みハイライトの dominantEmotion のみ保存）

## 6. 用語集

見どころ・クリップの状態・ジョブ・文字起こし・AI 解析・利用の段は、[用語カード](../../specs/quick-clip/term/highlight.md)を参照する。ここには、カードに定義がない用語だけを書く。

| 用語 | 定義 |
| ---- | ---- |
| 変化量 | 映像フレーム間のピクセル差分の大きさ。場面転換や激しい動きを検出するために使用 |
| QuickClip | さくっとクリップの英語サービス名 |
| 感情スコア | 文字起こしの各セグメントに対して算出した感情カテゴリ別のスコア（0.0〜1.0） |
| 感情フィルタ | ハイライト抽出時に重視する感情カテゴリの指定。`any` は全カテゴリの最大値を使用 |
| round-robin | motion → volume → emotion → motion → ... の順番で交互にピークを選択する集計方式 |
