# 信頼性

障害のときに、データを失わず、会話を止めず、失敗に気づけるようにする。対象は、DynamoDB のデータと、会話・バッチの処理である。

## 要求水準

- **データの復旧**: DynamoDB は、ポイントインタイムリカバリ (PITR) を有効にする。復旧できる範囲は、PITR に準ずる。prod のテーブルは、スタックを消しても残す
- **サービスの復旧**: 障害のときは、dev と prod へ再デプロイして復旧する ([デプロイ先](../../specs/deploy.md))
- **会話を止めない**: 想起・知識の判定・ノートの取得・出力の検査・親密度の更新が失敗しても、会話は続ける ([会話](../functional/conversation.md))。音声を作れなかった文は、文字だけを返す
    - 例外として、同意を読めないときは、会話を通さない ([同意](../functional/consent.md))
- **バッチは独立させる**: 集約・取得・通知・活動時間の学習は、バッチごとに別の Lambda と別の DLQ で動かす。取得の失敗やレイテンシが、集約の整合性に影響しないようにする。1 人の失敗で、ほかの利用者の処理を止めない
- **やり直せる集約**: 集約は、書き込みを先にしてカーソルを最後に進める。途中で落ちても、次の回で同じ内容をやり直せる ([集約バッチ](../../specs/batch/consolidate-conversations.md))
- **失敗に気づく**: バッチの失敗と、ブラウザで起きた失敗は、Admin にエラーとして届く。バッチの Lambda、ALB、DynamoDB の異常は、アラームが Admin に届ける ([エラー通知の経路](../../../admin/specs/flow/error-notification.md))

## やらないこと

- **稼働率や応答時間の数値の目標**: 根拠のある水準を、まだ決めていないため置かない
