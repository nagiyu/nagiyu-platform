# 勉強

キャラクターが、知らない話題や、利用者が気にしている話題を、自分で Web から調べて覚える。ユースケースは[知らない話題を聞く](../use-cases/ask-unknown-topic.md)と、[調べたことを通知で受け取る](../use-cases/receive-research-notification.md)。

## 要件

- 調べる契機は 3 つある ([勉強バッチ](../../specs/batch/acquire.md))
    - **会話からの依頼**: 会話で、調べ済みでない外部の話題が出たとき ([勉強の依頼](../../specs/term/study-topic.md))
    - **鮮度の確認**: 会話や通知で使われた話題に、期限の切れた WEB fact があるとき ([鮮度確認の依頼](../../specs/term/freshness-check-request.md))
    - **自発リサーチ**: 利用者が気にしている話題 (care が高いもの) を起点に、角度を広げて調べる ([探索の記録](../../specs/term/exploration.md))
- 知らない話題は、LLM に即答させず、コードで「勉強しておくね」に倒す。調べ済みの話題 (WEB fact を持つ話題) は、勉強に倒さず会話で答える。利用者自身のこと、一般常識、雑談は、勉強に倒さない
    - LLM は、学習済みの知識で即答してしまい、指示で止めても守らないため。コードで決めることで、プロンプトインジェクションにも強い
- 調べた内容は、バッチで話題に畳む ([集約バッチ](../../specs/batch/consolidate-conversations.md))
- WEB fact は、揮発性の区分で期限を持ち、期限を過ぎたものだけを調べ直す。話題ごとの件数にも上限を置く ([WEB fact](../../specs/term/web-fact.md))
    - 期限ごとに全話題を調べ直すと、会話に出ない話題まで調べてしまい、調べる回数の大半を使うため。使われた話題だけを調べ直す
    - 事実が増え続けると、会話のたびの費用が増え、古い事実と新しい事実が混ざって伝わるため
- 調べる回数に、利用者ごとの 1 日の上限を置く。会話からの依頼・鮮度の確認・自発リサーチを同じ枠で数え、全キャラクターで等分する。利用者 1 人の費用が、キャラクターの数だけ増えないようにするため。値は仮で、本番での使用感を見て調整する
- 利用者が 3 日話しかけていないキャラクターは、調べず、重要な通知も送らない。話しかけると再開する ([勉強の停止](../../specs/term/study-pause.md))。離れた利用者のために費用をかけず、更新されないまま重要な通知を出さないため
- キャラクターが就寝中のときは、調べない。利用者の活動する時間帯には、自発リサーチをしない ([生活サイクル](lifecycle.md))
- 自発リサーチの起点は、care が 1 以上の話題だけである。care は、利用者が会話で触れたときにだけ上がる。探索の結果として集まった話題 (care が 0) まで起点にすると、利用者の興味から離れた探索が連鎖するため
- 自発リサーチは、起点から軽い LLM で検索の角度を 1 つ作り、利用者がまだ知らなさそうな周辺 (関連するイベントや新作など) へ広げる。外れた情報が混ざってもよい。会話のネタになればよいため
    - 利用者の発言から得た事実は、角度を選ぶ手がかりにするだけで、センシティブな内容 (病気・家族・恋愛・お金など) には踏み込まない
    - 起点が気分・体調・悩み (憂鬱、眠気、疲れなど) のときは、解決策や公的な情報には広げず、気分転換になる軽い話題へ広げる。説教くさくならないようにするため
    - 同じ起点を続けて探索せず、最近選んだ角度と重ならないようにする
- 探索で得た話題は、利用者が会話で触れて care が上がるまで、ノートや通知にならない ([care](../../specs/term/care.md))

## やらないこと

- **自発リサーチだけでの care の上昇**: キャラクターの自発リサーチだけでは、care を上げない。上げると、利用者が一言も足していない話題でも、調べるほど care が育ち、「care が高い → もっと調べる → もっと育つ」と自己強化するため
- **使われていない話題の調べ直し**: 期限が来ても、会話や通知で使われない話題は調べ直さない
