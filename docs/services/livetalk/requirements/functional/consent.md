# 同意

会話を始める前に、利用規約・プライバシーポリシーへの同意と、18 歳以上であることの自己申告を求める。規約が改定されたときは、同意を取り直す。ユースケースは[利用規約に同意する](../use-cases/agree-to-terms.md)。

## 要件

- 利用者は、同意するまで会話できない。ホーム画面は同意のダイアログを出して入力欄を使えなくし、会話の API もサーバーで同意を確かめて断る ([ホーム画面](../../specs/screen/home.md)、[同意](../../specs/term/consent.md))
- 求めるのは、利用規約への同意、プライバシーポリシーへの同意、18 歳以上であることの自己申告の 3 つである。規約とポリシーの全文は、同意の前に読める ([利用規約](../../specs/screen/terms.md)、[プライバシーポリシー](../../specs/screen/privacy.md))
- 同意は、規約とポリシーの版と日時を、利用者ごとに記録する。今の版と記録が合わないときは、取り直す
- 版が上がったときの取り直しは、改定のお知らせとして出す
    - 前の版に同意した記録のある利用者には、変わった文書ごとに、同意した版より後の改定の要点を示す。記録のない利用者には、初回の案内を出す
    - 18 歳以上の自己申告は、記録があれば取り直さない。年齢は規約の版と関係なく、改定のたびに求めると、初回の画面にもう一度なったように見えるため
    - 同意を取り直しても、今の版に同意済みの文書の記録と、記録済みの自己申告は、日時ごと残す。同意の記録は、利用者が実際に同意した時点を示すものであるため
    - 改定の要点は、規約・ポリシーの画面にも改定履歴として載せる。履歴を足しても、条文は変わらないので、版は上がらない
- 会話の API は、同意を読めないときは通さない。同意は規約上のゲートで、会話の処理も同じ保存先に依存し、通しても会話は成り立たないため
- 断られた画面は、その場で同意のダイアログを開き直す。チェックは外れた状態から始め、新しい版を読まずに同意できないようにする
- 退会と記憶の削除は、同意が無くても受け付ける。同意を取り下げた人こそ、自分のデータを消せる必要があるため。閲覧は新しい処理を起こさないので、同意を求めない

## やらないこと

- **会話以外の API で同意を確かめること**: 同意が守るのは、利用者の発話を外部の LLM に渡し、会話や記憶として残すことで、それを新しく起こすのは会話だけであるため
- **ダイアログ以外での改定の通知**: メールなどでは知らせない。リブトークは、メールアドレスと送信の仕組みを持たないため
