# セーフティ

利用者が自殺や自傷をほのめかしたとき、LLM に任せず、キャラクターの口調で心配を伝え、相談できる窓口を案内する。ユースケースは[危険な発言のあとの案内を受ける](../use-cases/receive-safety-guidance.md)。

## 要件

- 入力と出力の両方で介入する ([セーフティ](../../specs/term/safety.md))
    - **入力**: 発言が、自殺・自傷・絶望・手段への言及・危機的状態を示す語に当たったら、LLM を呼ばず、キャラクターの口調の固定の応答を返す
    - **出力**: 応答を Moderation で検査し、止められたら、元の応答を音声にせず、差し替えの応答を返す
- どちらの介入でも、相談できる窓口を示す。窓口は、いのちの電話、よりそいホットライン、TELL Lifeline、緊急時の 119 である ([ホーム画面](../../specs/screen/home.md))
- 窓口は、キャラクターの口調で心配を表明したうえで案内する。番号を機械的に貼り付けるだけにしない
- 検出のたびに、記録を残す。Character.AI や OpenAI の訴訟の事例を踏まえ、開発者が責任を問われたときの証跡にするため。記録は、運用者が全利用者を横断して確かめられる ([セーフティの横断レビュー](safety-review.md))。保持期間は[データの保持](../non-functional/data-retention.md)
- 出力の検査の呼び出しが失敗したときは、止めずに通常の応答を通す

## やらないこと

- **LLM の安全機構に任せること**: LLM が持つ安全機構は不十分なおそれがある。Character.AI や OpenAI の訴訟の事例で、開発者の責任が問われているため、入力のキーワード検出を主な防御とし、出力の検査を補助にする
- **誤検出をなくすために、検出を緩めること**: 語に当たると、危険の意図がなくても会話が中断されることがある。安全側に倒しているため、許容する
