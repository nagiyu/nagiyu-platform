# 記憶

キャラクターが、会話から利用者についての事実を覚え、関連する話題だけを思い出して話す。利用者は、覚えられていることを見て、消せる。ユースケースは[記憶を見る・消す](../use-cases/view-and-delete-memory.md)。

## 要件

- 会話から、利用者についての事実 (SELF fact) を話題 (Topic) ごとに覚える。同じ話題に、キャラクターが調べたこと (WEB fact) が同居し、話したことと調べたことがつながる ([ドメインモデル](../domain-model.md)、[Topic](../../specs/term/topic.md))
- 覚えるのは、バッチで畳むときである。会話の応答の中では覚えない ([集約バッチ](../../specs/batch/consolidate-conversations.md))
- 会話では、発言に関連する話題だけを思い出す。関連度だけで選び、利用者が触れていない話題を持ち出さない。関係のない話題が湧いてくることを避けるため
- 覚えていることには、いつ聞いたか・いつ調べたかが付く。いつのことかは、本文に年月日で持たせる。終わったことは、終わったと書く
- 利用者は、覚えられていること (SELF fact) を話題ごとに見られる ([記憶画面](../../specs/screen/memory.md))
- 利用者は、覚えられていることを 1 件ずつ削除できる ([記憶 API](../../specs/api/memory.md))
    - 削除は物理削除で、その場で話題の要約を作り直す。削除した内容は、以降の応答にも、要約にも残らない
    - 畳み済みの会話は、以降の会話の文脈に戻らない
    - 要約の作り直しに失敗しても、削除は残る。押し直すと、要約だけを作り直す

## やらないこと

- **記憶の編集**: 編集しても、要約と会話履歴に古い情報が残り、キャラクターが言い続けるため。削除なら、要約を作り直して残らないようにできる
- **Tier やピン留め**: 利用者に見せない。想起を関連度で行うので、利用者に重要度の階層や、常に思い出すピンの概念を見せる必要がないため
- **WEB fact の表示と削除**: 記憶画面に出さず、削除の対象にしない。画面は「私について覚えていること」に限る。調べたことが混ざらないようにするため
- **会話履歴の改変**: 記憶を消しても、会話履歴は書き換えない。履歴を改変する感じを避けるため
- **終わった話題の自動削除**: 終わった話題や過ぎた予定を、自動では消さない。いつのことかを本文に残し、終わったことは終わったと書くことで扱う
