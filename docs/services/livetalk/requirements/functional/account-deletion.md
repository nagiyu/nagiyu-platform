# 退会とデータの削除

利用者が自分で退会し、リブトークに残る自分のデータを消す。ユースケースは[退会してデータを消す](../use-cases/delete-account.md)。

## 要件

- 利用者は、ホーム画面から退会できる。削除の前に、削除する範囲と、元に戻せないことを示し、理解したことの確認を求める ([ホーム画面](../../specs/screen/home.md))
- 退会すると、利用者のデータをすぐに削除する ([アカウント API](../../specs/api/account.md))
    - 利用者の ID の配下にあるものを、種類を挙げずに走査して消す。データの種類が増えても、削除の対象に自動で含まれる
    - 途中で失敗したときは、成功にせず失敗として返す。やり直すと最後まで消える。完全な原子性は持たない
    - 退会は本人の分だけを対象にし、ほかの利用者には及ばない
- セーフティの検出の記録だけは、消さず、利用者から切り離して残す ([セーフティ](safety.md))
    - 利用者の ID を、元に戻せないランダムな匿名の持ち主に付け替える。ID から決まった値を作る擬似的な匿名化は採らない。横断で束ねる便利さより、個人識別子を切り離すことを優先するため
    - 検出から 3 年で、自動で消える。匿名にしても期限は引き継ぐ ([データの保持](../non-functional/data-retention.md))
    - 確認のダイアログにも、この期限を示す
    - 残す理由は[セーフティ](safety.md)にある
- 開示請求には、運営者が人手で応じる
- 退会のあとは、Auth のサインアウトへ移る。サインアウトは、Cookie を発行する Auth に集約している ([認証の規約](../../../../platform/rules/authentication.md))
- 対象は、リブトークのデータだけである。Google アカウント自体、ほかのサービスのデータ、ロールは、退会の処理で変えない

## やらないこと

- **論理削除と猶予期間**: このサービスの規模に対して過剰なため。削除は不可逆なので、確認を必須にする
- **セルフサービスのデータのエクスポート**: 法的に必須なのは、開示請求への対応である (個人情報保護法)。これは人手で応じられるため、公開の前に塞ぐべき削除の導線に絞る
