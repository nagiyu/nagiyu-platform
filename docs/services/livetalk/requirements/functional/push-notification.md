# Push 通知

キャラクターが、調べたことや近い予定を、利用者の端末へ Web Push で知らせる。通知を開くと、そのキャラクターが第一声で話し始める。ユースケースは[調べたことを通知で受け取る](../use-cases/receive-research-notification.md)と[通知を有効にする](../use-cases/enable-notifications.md)。

## 要件

- 通知は 2 種類ある ([通知バッチ](../../specs/batch/notify.md))
    - **平常通知**: 日常の呼びかけ。利用者の会話の間隔に合わせて決まる
    - **重要通知**: 近い予定 (今日から 14 日以内) のある話題の知らせ。時間帯に関係なく送る
- 通知は、利用者の購読すべての端末に送る ([購読の API](../../specs/api/push.md))
- 平常通知は、利用者が活動する時間帯にだけ送る。間隔は、利用者の直近の会話の間隔の中央値に合わせ、活発な利用者ほど短くする。反応のない通知を重ねるたびに間隔を延ばし、一定を超えたら止める
- 1 日の上限を置く。平常通知は利用者ごとに 1〜3 件で、1 回の実行では 1 キャラクターだけに送る。重要通知はキャラクターごとに 1 件
- キャラクターが就寝中のときは、どちらも送らない ([生活サイクル](lifecycle.md))
- 重要通知は、同じ話題・同じ予定の日付を 1 度だけ送る。日付が変わったときは、新しい予定として改めて送る
    - 期限切れの WEB fact を持つ話題は、確認が済むまで重要通知にしない。古い情報で通知しないため
- 利用者が 3 日話しかけていないキャラクターは、重要通知を送らない。平常通知は、話題名を入れない文面だけを使う ([勉強の停止](../../specs/term/study-pause.md))。勉強していない事実を言わずに済ませるため
- 平常通知の口調は、最後の発言からの経過日数で変える
- 通知を開くと、通知元のキャラクターに切り替わり、通知の本文が第一声になる。返信の下書きが入力欄に入り、送信は利用者が押す ([通知から会話への経路](../../specs/flow/notification-open.md))
    - 自動で送らないのは、音声の再生が利用者の操作を要するため。操作のない自動送信では、音声が鳴らない。誤ってタップしたときの、意図しない送信も防げる
- 通知の購読が無効になった宛先は、送信のときに削除する
- 通知は、キャラクターの働きかけとして、生成・送信・消化をキャラクターで揃える ([キャラクター](characters.md))

## やらないこと

- **利用者を追い続けること**: 反応のない通知を重ねると、間隔が延び、止まる。利用者が戻ってこなくても、追わない。「追わない」姿勢を、ほかのコンパニオンとの違いにするため
- **通知の自動送信**: 開いたあとの返信を、自動では送らない。理由は上のとおり
