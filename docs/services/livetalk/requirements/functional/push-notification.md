# Push 通知

キャラクターが、調べたことや近い予定を、利用者の端末へ Web Push で知らせる。通知を開くと、そのキャラクターが第一声で話し始める。ユースケースは[調べたことを通知で受け取る](../use-cases/receive-research-notification.md)と[通知を有効にする](../use-cases/enable-notifications.md)。

## 要件

- 通知は 2 種類ある ([通知バッチ](../../specs/batch/notify.md))
    - **平常通知**: 日常の呼びかけ。利用者の会話の間隔に合わせて決まる
    - **重要通知**: 近い予定のある話題の知らせ。時間帯に関係なく送る
- 通知は、利用者の購読すべての端末に送る。使えなくなった購読は、送るときに取り除く ([購読の API](../../specs/api/push.md))
- 平常通知は、利用者が活動する時間帯にだけ送る。反応のない通知を重ねるたびに間隔を延ばし、一定を超えたら止める
- 1 日の上限を置く。平常通知は利用者ごとに、重要通知はキャラクターごとに数える。平常通知は 1 回の実行で 1 キャラクターだけに送る
- キャラクターが就寝中のときは、どちらも送らない ([生活サイクル](lifecycle.md))
- 重要通知は、同じ話題・同じ予定を 1 度だけ送る。期限切れの WEB fact を持つ話題は、確認が済むまで重要通知にしない
- 利用者が 3 日話しかけていないキャラクターは、重要通知を送らない。平常通知は、話題名を入れない文面だけを使う ([勉強の停止](../../specs/term/study-pause.md))
- 平常通知の口調は、最後の発言からの経過日数で変える
- 通知は、キャラクターごとに生成・送信・消化する。通知を開くと、通知元のキャラクターに切り替わり、通知の本文が第一声になる。返信の下書きが入力欄に入り、送信は利用者が押す ([通知から会話への経路](../../specs/flow/notification-open.md))

## やらないこと

- **利用者を追い続けること**: 反応のない通知を重ねると、間隔が延び、止まる。「追わない」姿勢を保つため ([通知バッチ](../../specs/batch/notify.md))
- **通知の自動送信**: 開いたあとの返信を、自動では送らない。音声の再生に、利用者の操作が要るため ([通知から会話への経路](../../specs/flow/notification-open.md))
