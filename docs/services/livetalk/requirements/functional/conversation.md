# 会話

利用者が文字で発言し、キャラクターが人格に沿って応答を文字と音声で返す。ユースケースは[キャラクターと話す](../use-cases/talk-with-character.md)。

## 要件

- 利用者は、文字で発言を送れる ([ホーム画面](../../specs/screen/home.md)、[チャット API](../../specs/api/chat.md))
- 応答は、文字と音声で返る
    - 文字は、作りながら順に表示される
    - 音声は、文ごとに作って順に再生される。音声に合わせて、キャラクターの口が動く ([キャラクターの見せ方](character-presentation.md))
- 応答は、キャラクターごとの性格・口調・好みに沿う ([キャラクター](characters.md))
- 発言に関連する話題を思い出して、応答に使う。話題は関連度だけで選ぶ ([記憶](memory.md))
- 今日の日付 (日本時間) を踏まえて話す。日時のある話題は今日と比べてから話し、終わった予定を「これから」のこととして話さない
- 発言と応答は会話履歴に残り、記憶の元になる ([データの保持](../non-functional/data-retention.md))
- 同意が無い利用者の会話は、サーバーも断る ([同意](consent.md))
- 危険な発言は、LLM に任せず専用の応答にする ([セーフティ](safety.md))
- 知らない話題は、即答せず調べる ([勉強](study.md))
- 同じ利用者の同時の呼び出しは 1 本まで、短時間の呼び出しの回数には上限を置く。上限に当たったときは、やわらかい文言で待たせる (上限の値は[チャット API](../../specs/api/chat.md))
    - 認証さえ通れば、1 回の呼び出しごとに LLM と音声合成が走る。悪意がなくても、PWA の再送やクライアントの不具合で、LLM の課金が走るおそれがあるため
    - 2 本目はキャンセルせず拒否する。応答の保存が冪等でないため、拒否のほうが安全
    - 上限の保存先が使えないときは、数えずに通す。コストの保護より、会話が使えることを優先する (同意を読めないときは、通さない。[同意](consent.md))
- 想起・知識の判定・ノートの取得・出力の検査・親密度の更新が失敗しても、会話は続ける ([信頼性](../non-functional/reliability.md))

## やらないこと

- **会話のたびの集約**: 話題への集約は、会話の応答の中では行わず、バッチに寄せる。会話の途中で集約の LLM を呼ばないため ([会話の経路](../../specs/flow/conversation.md))
