# WEB fact

Web リサーチで得た外部の事実。[Topic](./topic.md) の配下に 1 件ずつ持つ。

## 説明

揮発性の区分ごとに、再確認の期限 (nextReview) と保持件数が決まる。

| 区分 | 再確認の間隔 | 保持の上限 |
|---|---|---|
| stable | なし (期限を持たない) | 10 件 |
| low | 30 日 | stable 以外の合計で 20 件 |
| medium | 7 日 | 同上 |
| high | 1 日 | 同上 |

- 上限を超えた分は、区分ごとに観測日時の古い順に消す。消すのは集約バッチ
- 確認が要る事実は、stable 以外で、再確認の期限を過ぎたもの
- 読む側は、観測日時の新しい順に 20 件までを使う。会話のプロンプトは 5 件、ノートは 10 件、探索の角度の生成は 5 件まで
- 作るのは集約バッチだけ。新しい事実は、既存の事実と見比べて追加・置き換え・重複 (観測日時と期限の更新だけ) のどれかで入れる

## 理由

- 再確認の期限は、揮発性の区分で決める。在庫・価格・順位のような変わりやすい事実と、作品の事実のように変わりにくい事実に、一律の間隔で調べ直すと、古い内容の要約を量産する。stable は再確認しない
- Topic あたりの保持の上限は、stable と、それ以外 (low・medium・high) で別々に数える。合計で数えると、stable だけで上限が埋まった Topic では、新しく調べた stable 以外の事実 (ライブの日程など) が足したそばから消え、新しい情報が残らない。自発リサーチの間隔の判定も効かず、毎回同じ Topic を調べ直す
    - stable を数えないだけにしないのは、stable の区分を集約の LLM が付けるからである。付け間違えると、上限なしで溜まる
- 置き換えた古い事実は、残さず消す。残すと件数の上限を圧迫し、古い事実と新しい事実が混ざる
- 重複と判定した新しい事実は保存せず、元の事実の観測日時と再確認の期限を更新する。自発リサーチの間隔の判定が最新の観測日時を見るので、更新しないと、毎回同じ Topic を調べ直す
- 会話は、想起した Topic の WEB fact を全件プロンプトに入れるので、事実が増えるほど原価が増え、古い事実と新しい事実が混ざって伝わる。dev では 1 つの Topic に WEB fact が 100 件ほど溜まった。読む側は、区分を問わず観測日時の新しい順に一定の件数までを使う
- すでに溜まっている Topic のための掃除の仕組みは作らない。使われる Topic は、会話 (鮮度の確認) か自発リサーチを経て必ず集約を通り、そこで上限まで減る。集約を通るまでの間も、読む側が新しい側の上限までしか取らないので、原価は膨らまない。使われない Topic は溜まった件数のまま残るが、害は保存量だけである
