# 探索の記録

自発リサーチで起点にした [Topic](./topic.md) ごとの、最後に探索した時刻と、最近の角度の記録。

## 説明

- 角度は、起点の Topic から広げた Web 検索の語句。LLM が 1 つ作る (会話と同じモデルを、推論なしで呼ぶ)。作れなかったときは「{主題} 最新情報」に落とす
- 角度の生成には、起点の要約、利用者の発言由来の [SELF fact](./self-fact.md) (最大 5 件)、すでに知っている [WEB fact](./web-fact.md) (新しい側 5 件)、最近の角度を渡す
- 時刻は探索を試した時点で残し、成否は問わない。最近の角度は新しい順に 5 件までを保つ
- 探索の結果は別の Topic に集約されうるため、起点の WEB fact の観測日時は進まない。時刻の記録があるのはそのためである
- Topic のヘッダとは別のアイテムに持つ。ヘッダは集約が楽観ロックで書き換えるため

## 理由

- 自発リサーチの検索は、起点の Topic から広げた角度を 1 つ作り、1 回の検索で探索する。検索の回数は増やさず、1 日の枠 ([勉強バッチ](../batch/acquire.md)) の内側に収める。常に「{主題} 最新情報」で調べる方式では、「ボカロが好き」と話しても、ライブの情報のような周辺の話題が出てこず、同じ話題の最新情報を繰り返し取ってくるだけになる
- 角度の生成に失敗したときは、「{主題} 最新情報」に落とす
- 外れた情報が混ざってもよい。会話のネタになればよいので、利用者がまだ知らなさそうな周辺 (関連するイベント・新作・関わる人物など) を選ばせる。すでに知っている事実と、最近探索した角度には重ならないようにする。センシティブな内容には踏み込まず、趣味・関心の範囲で広げる
- 起点が気分・体調・悩み (憂鬱、眠気、疲れなど) のときは、解決策や公的な情報には広げず、気分転換になる軽い話題へ広げる。説教っぽくならないようにするためである
- 起点は care 1 以上の Topic に限る。care は利用者が会話で触れたときにだけ上がるので、1 以上は利用者の興味を表す。探索の結果として集約された care 0 の Topic まで起点にすると、利用者の興味から離れた探索が連鎖する
- 探索の記録を、Topic とは別のアイテムに持つ。探索の結果は別の Topic に集約されうるので、起点の WEB fact の観測日時が進まず、観測日時だけでは間隔を空けられない。dev では、同じ起点を毎時 10 回調べていた。Topic のヘッダに足さないのは、集約がヘッダを楽観ロックで書き換えるためで、[ノート](./note.md)の見送りの記録も同じ置き方にしている
- 探索で得た情報の出し先は、会話だけにする。探索の結果は care 0 の Topic に集約されることが多く、care を閾値にするノートや通知には出ない。会話では、発話が調べた Topic に直接近いときだけ想起される (「ボカロのイベント行きたい」には出るが、「ボカロばっか聴いてる」には出ない)。想起を広げて何でも引っ張ってくるのも望ましくない
