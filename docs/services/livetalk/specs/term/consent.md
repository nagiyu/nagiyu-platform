# 同意

利用者が、利用規約・プライバシーポリシー・18 歳以上であること (自己申告) に応じた記録。ホーム画面で会話を始める前に求める。

## 説明

- 記録するのは、規約の版と同意日時、プライバシーポリシーの版と同意日時、18 歳以上の自己申告と日時
- 同意を取り直しても、今の版に同意済みの文書と、記録済みの 18 歳以上の自己申告は、記録した日時のまま残る
- 有効と見なすのは、3 つがそろい、規約とプライバシーポリシーの版が今の版 (どちらも `1.1.0`) と一致するときだけ。版が上がると、再び求める
- 規約・ポリシーの同意が (前の版のものも含めて) 記録に残っている利用者に、版が上がったあとで求めるときは「改定」として扱う。画面は、変わった文書の改定の要点を示し、記録済みの 18 歳以上の自己申告は求め直さない。記録がなければ「初回」として扱う
- 同意は利用者ごとに 1 件で、プロフィールに保存する。退会すると消える
- 求めるのはホーム画面の同意のダイアログで、同意するまで入力欄は無効のまま残る
- [チャット API](../api/chat.md) も、同意が有効でなければ会話を断る (403)。画面はそれを受けると、同意のダイアログを開き直す
- 会話以外の API (記憶・ノートの閲覧、通知、退会など) は、同意を確かめない

## 理由

- 同意をサーバーで確かめるのは、会話の API だけにする。同意が守るのは、利用者の発言を外部の LLM に渡し、会話や記憶として残すことで、それを新しく起こすのは会話だけである。画面のダイアログだけで確かめると、API を直接呼べば同意なしで会話でき、開いたままのタブで規約の版が上がっても会話を続けられてしまう
- 退会と記憶の削除は、同意がなくても受け付ける。同意を取り下げた人こそ、自分のデータを消せる必要があるためである。閲覧系は、新しい処理を起こさないので求めない
- 同意を読めないときは、会話を通さない。会話のロックとレートリミットは障害時に通すが、同意は規約上のゲートなので、扱いを逆にする。会話の処理も同じ保存先に依存するので、通しても会話は成り立たない
- バッチは同意を確かめない。同意が切れた利用者にも、記憶を使った通知が届きうる
- 規約・ポリシーの改定は、同意の取り直しのダイアログで知らせる。初回と同じダイアログだけでは、改定したことも、何が変わったかも分からず、既存の利用者には最初の画面がもう一度出たように見える。そこで、前の版に同意した記録のある利用者には、改定のお知らせとして、同意した版より後の改定の要点を文書ごとに示す
    - メールなど、ダイアログ以外の通知はしない。メールを送るには、リブトークが持たないメールアドレスと送信の仕組みが要る
    - 18 歳以上の自己申告は、記録があれば取り直しで求めない。年齢は規約の版と関係がなく、改定のたびに求めると、初回の画面に見える原因が残る
    - 今の版に同意済みの文書と、記録済みの自己申告は、日時ごと残す。同意の記録は、利用者が実際に同意した時点を示すものだからである
    - 改定の要点は、版ごとに `services/livetalk/web/src/lib/legal/revisions.ts` の 1 か所に持つ。同意のダイアログと、規約・ポリシーの画面の改定履歴が、同じものを読む。改定履歴は条文の外にあるので、履歴を足しても条文は変わらず、版を上げる必要もない

## 手順

規約またはプライバシーポリシーの版を上げるとき。

1. `services/livetalk/core/src/constants.ts` の版 (`LIVETALK_TERMS_VERSION`、`LIVETALK_PRIVACY_VERSION`) を上げる。規約とポリシーの版は同時に上げる運用で、片方だけを上げない
2. `revisions.ts` の `termsRevisions`、`privacyRevisions` の末尾に、新しい版の施行日と改定の要点を足す。要点を足さずに版だけを上げると、改定のお知らせに変わった点が出ない
3. 最新の要点の版が、同意の判定に使う版と一致することは、`services/livetalk/web/tests/unit/lib/legal/revisions.test.ts` が確かめる
