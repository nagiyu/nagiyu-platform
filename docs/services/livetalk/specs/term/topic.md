# Topic (話題)

話題 1 つぶんの知識・記憶をまとめた集約体。「話したこと」と「調べたこと」を同じ話題でつなぐ。

## 説明

- 構成は、ヘッダ 1 件と、その配下の [SELF fact](./self-fact.md) と [WEB fact](./web-fact.md) の複数件である
- ヘッダの持ち物: 主題 (subject)、正規化した要約、カテゴリ、[care](./care.md)、座標 (embedding)、依頼由来の依頼文と依頼日時 (あるときだけ)
- 作る・更新するのは集約バッチだけ。会話の応答では書かない
- 想起は関連度だけで行う。会話では、発話の埋め込みとの類似度が 0.4 以上の上位 5 件を文脈に入れる。さらに、その 5 件との類似度が 0.8 以上の Topic を最大 2 件足す
- 集約時の名寄せ候補は、類似度 0.4 以上の上位 8 件である
- SELF fact を利用者が削除すると、その場で要約を作り直す

## 理由

- 知識・記憶の単位を Topic にし、その配下に [SELF fact](./self-fact.md) (話したこと) と [WEB fact](./web-fact.md) (調べたこと) を束ねる。同じ話題で両方が自動的につながり、「二郎系が好きと言っていたね、新店ができたよ」のように、両方を踏まえて応える。別々に持つと、つながらず、まとまった要約にもならない
- 元データ (会話・Web 取得) は、そのまま書き足し続けず、バッチで Topic に畳む。足し続けると、同じ話題が重複して膨らむ (dev で同じ話題が十数件になった)。畳み込みは[集約バッチ](../batch/consolidate-conversations.md)に寄せ、会話の応答の途中では、集約のための LLM を呼ばない
- 想起は、発話との関連度だけで選ぶ。話題の注目度 ([care](./care.md)) や好みを、常に文脈へ入れることはしない。関係のない話題が会話に湧いてくる (コーヒー病) のを、構造で避けるためである。素性 (名前・制約) 以外のコアプロフィールも、常時は入れない
- グラフ DB・ベクトル DB は入れない。話題どうしの関連は事前に計算せず、想起のときに、埋め込みの近さでその場で求める
- SELF fact の削除は、物理削除と要約の作り直しで行う。LLM に「言わないで」と頼む方式は、削除したあとも LLM が言い続ける。削除した内容を要約から取り除けば、以降の応答にも、導出される内容にも残らない
