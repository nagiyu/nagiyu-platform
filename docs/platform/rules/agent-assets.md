# エージェント資産の置き場所の規約

AI エージェント向けの知識・手順・道具を、どこに置くかの規則と、その理由。放置すると同じ知識が重複して散らばる。新しい規則・手順・道具を足すときは、まずここで置き場所を判断する。置き場所を強制する設定ファイルはないため、出典は持たない。

## レイヤ

| レイヤ | 配置 | いつ効くか | 置くもの |
|---|---|---|---|
| 常時ロード | `CLAUDE.md` | 毎ターン | 全作業に効く短い鉄則・ロール定義・MUST NOT |
| Skill | `.claude/skills/<name>/` | 関連したときだけ本文が載る (`description` のみ常時) | たまに使う手順・道具 (スクリプトやテンプレートを同梱できる) |
| サブエージェント | `.claude/agents/` | spawn 時に別コンテキストで動く。定義はそのサブエージェントの中でだけ常時載る | コンテキストの隔離が要る作業 (実装、fresh-eyes レビュー)。モデルを指定できる |
| docs | `docs/` | 必要なときに参照する | 要件 (何を満たすか)・仕様 (今のコードがどう動くか)・規約 (守る規則とその理由)。分類は [docs の書き方](./docs.md) |
| 他ツール用 | `AGENTS.md`、`.github/agents/`、`.github/copilot-instructions.md`、`.specify/` | 別ツール側 | Codex・Copilot Agent・spec-kit 向けの指示。Claude の運用とは別系統 |

仕様は文面だけを単独で直さず、コードを変える PR で `docs-write` スキルに沿って作り直す。

## 置き場所の判断

次の順に問い、最初に当てはまったものに置く。

1. 全作業に常に効く短い鉄則か: `CLAUDE.md` (常時ロード)
2. 物量のある作業を、本体の文脈から切り離したいか: サブエージェント
3. たまに使う手順で、スクリプトやテンプレートを同梱したいか: Skill
4. 今のコードの挙動、満たすべきこと、守る規則とその理由か: docs

### 全作業に常に効くものは `CLAUDE.md` に置く

言語の規則、MUST NOT、セッションロールと継ぎ目モデルの根幹、実装中つねに効くガードレールが当たる。全ターンに効くため、関連したときだけ載る Skill にすると抜け落ちる。実装担当にだけ効く規約は `.claude/agents/implementer.md` に持たせる。

### 常時ロードするほどではないが、その都度読ませると漏れる手順は Skill にする

環境固有のハマりどころ (共通ライブラリのビルド、Playwright の準備) は、スクリプトを同梱して「覚える」を「実行する」に置き換える。長い手順 (PR 作成、リリース、docs の執筆) は、関連したときだけ展開し、常時ロードを軽くする。

Skill の `description` は、モデルがその 1 行で起動を判断するため、「いつ使うか」が伝わるよう三人称で書く。

### 物量のある作業と、コンテキストの隔離が目的の作業はサブエージェントにする

- 実装とテストのように物量があり、オーケストレーターの文脈を圧迫する作業。別のモデルを指定してコストを抑える。
- コンテキストの隔離そのものが目的の作業 (fresh-eyes レビュー)。オーケストレーターは実装の方針と会話履歴を抱えているため、同じ文脈でレビューしても先入観を排せない。別コンテキストに diff と成果物だけを渡すことで、白紙の視点の検証が成立する。

人の判断が要る作業はサブエージェントにしない。サブエージェントは走り出すと人が介入できないためである。セッションとの使い分けは `CLAUDE.md` の「なぜセッションを分けるのか」を正とし、実測は [Claude セッション運用の規約](./claude-sessions.md) にある。

## 他ツール用の資産

### `AGENTS.md` と Claude の運用は独立させる

`CLAUDE.md` は Claude 専用の運用ハンドブックとして自己完結させ、`AGENTS.md` の指示に依存しない。両者を互いの参照で成り立たせると、片方の変更がもう片方の運用を壊すためである。

### `.github/agents/` と `.specify/` は消さずに並存させる

`.github/agents/` (`docs.write`、`task.proposal`、`task.implement` など) と `.specify/` (spec-kit) は Copilot Agent と spec-kit 用で、Claude の運用とは別系統として今も置いてある。Claude 用に同種の手順が欲しいときは、これらを書き換えず、`.claude/skills/` に Claude 用の Skill を新しく置く。
