# Issue と PR の分類の規約

Issue を後から絞り込めるようにするための、分類の規則と、その理由。主な用途は、リリースのときに「どのサービスに何が入るか」を確認することである。分類を強制する設定ファイルはなく、Issue テンプレートがタイトルの初期値を入れるだけなので、出典は持たない。

## 軸

### 分類する軸は 3 つとし、軸ごとに表す場所を 1 つに決める

| 軸 | 表す場所 | 付ける人 |
|---|---|---|
| 種別 (バグ・機能追加など) | タイトルのプレフィックス | 起票者 |
| サービス | ラベル | 起票者 |
| リリース | マイルストーン | 人 |

同じ情報を 2 か所に書かない。2 か所に書くと、片方だけ直されて食い違うためである。

### ラベルはサービス専用にする

リリース対象の確認ではサービス単位の絞り込みが最もよく効く。種別までラベルにすると、ラベルが複数の軸の混在になり、どれを付けるべきか迷って付け忘れの原因になる。

## タイトル

### タイトルは `[種別] 内容` の形で書く

種別は次のいずれかとする。

| プレフィックス | 種別 |
|---|---|
| `[Feature]` | 新規機能 |
| `[Bug]` | バグ修正 |
| `[Refactor]` | リファクタリング |
| `[Docs]` | ドキュメント更新 |
| `[CI]` | CI/CD 更新 |
| `[Infra]` | インフラ更新 |
| `[Chore]` | その他 |

- 区分は PR テンプレートの「変更種別」(`.github/pull_request_template.md`) とそろえる。Issue と PR を同じ分類で追えるようにするためである。
- 内容は「何が起きているか」または「何をするか」を文で書く。
- 連番やシリーズ名は、プレフィックスではなく内容の側に書く。
    - 例: `[Refactor] 共通化 C1: DynamoDB エラーの扱いを共通化する`

## サービスラベル

### サービスごとに 1 つのラベルを用意し、名前はサービスのディレクトリ名と同じにする

例は `stock-tracker`、`livetalk`。ディレクトリ名と同じにすると、ラベルとサービスの対応表を持たずに済む。

### どのサービスにも属さないものには `platform` を付ける

共通ライブラリ、共通インフラ、CI、`docs/platform/` の文書、開発運用が当たる。コードの置き場所で線を引く [docs の書き方](./docs.md) と同じで、`services/<name>/` にあるもの (文書は `docs/services/<name>/`) はそのサービスのラベル、それ以外は `platform` である。サービスを持たないものにラベルがないと、リリース対象の確認で絞り込みから漏れる。

### 複数のサービスにまたがる場合は、該当するラベルをすべて付ける

どのサービスで絞り込んでも、リリース対象の確認で漏れないようにするためである。

### 起票者が起票時に付ける

どのサービスかは判断を要さずに決まる。後から付けることにすると、付け忘れた Issue が絞り込みから漏れるためである。

## マイルストーン

### マイルストーンはリリースの版 (`vX.Y.Z`) とリリース先が未定のもの (`Backlogs`) に使い、人が付ける

どのリリースに入れるかは判断を伴うためである。

## サブ Issue

### サブ Issue にはラベルもマイルストーンも付けない

分類は親 Issue だけで行う。リリース対象の確認は親 Issue を見れば足りる。付けるものと付けないものが混ざると、絞り込みの結果が中途半端になるため、付けないことで統一する。

## PR

### PR にはラベル・マイルストーン・種別プレフィックスを付けない

分類は関連 Issue で行う。PR の種別は PR テンプレートの「変更種別」で表しており、タイトルにも書くと同じ情報が 2 か所になる。タイトルは「何を変えるか」を文で書く。

## 対象外

定期実行のワークフローが起票する Issue は、本規約の対象外とする。タイトルは `[Blog]`、`[Exploratory]`、`[NPM管理]`、`[Refactoring]` などワークフローごとの固有のプレフィックスで、ラベル (`weekly-check`、`blog-article` など) も、ワークフローごとの識別と重複起票の検出に使うためである。起票の振る舞いは [定期の Issue 起票](../specs/ci/scheduled-issues.md) にある。
