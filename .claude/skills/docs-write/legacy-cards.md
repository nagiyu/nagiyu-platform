# 旧配置の仕様カードを直す

旧配置 (`docs/specs/`) のカードを直すときの手順。新しい配置の文書は [SKILL.md](SKILL.md) に従う。旧配置のカードは新しい配置へ移すまで残り、今の検査のまま通る。カードは**今のコードがどう動くか**の要約で、正本はコードである。カードの文面だけを単独で直さず、コードを変える PR の中で、コードを読んでこの手順に沿って作り直す。

## 使うとき

- 変更したファイルが、いずれかのカードの `sources` に含まれる
    - 探し方: `grep -rl "<変更したファイルのパス>" docs/specs`
- 新しいバッチ・通知経路・画面・API・用語を足した
- `node .github/workflows/scripts/docs-structure.mjs check` が落ちた

## 手順

1. **コードを読む**: 今の挙動はコードから取る。ADR は「なぜ」の参照先としてだけ使い、挙動の根拠にしない。ADR や既存のカードとコードが食い違ったら、コードを正とし、食い違いを PR で報告する
2. **型に沿って書く**: 種別 (batch / flow / term / screen / api) ごとの見出しは、雛形 (`docs/services/_template/specs/` の同じ種別のファイル) に従う。ただし用語カードの `## 関連

- [docs/specs/README.md](../../../docs/specs/README.md): 旧配置の仕様カードの置き場
- [SKILL.md](SKILL.md): 新しい配置の文書の書き方
