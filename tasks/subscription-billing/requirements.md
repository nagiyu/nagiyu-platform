# サブスクリプション課金の土台 要件定義書

---

## 1. ビジネス要件

### 1.1 背景・目的

- プラットフォームには、運営コストのかかる機能がある (livetalk の OpenAI 呼び出し、quick-clip の文字起こしと LLM、codec-converter の AWS Batch など)。一方で、収益の手段はない。
- 認可はロール単位で行っている。各サービスはロールから導かれる権限を確かめる。課金を「ロールを付け外しする入口の一つ」として扱えば、各サービスの権限チェックの作りを変えずに、有料ユーザーの操作範囲を広げられる。
- 本対応では、その入口 (課金で付くロールの管理と、Stripe との連携) と、課金に必要な公開ページを作る。各サービスで何を有料にするかは扱わない。

### 1.2 対象ユーザー

- **利用者**: プラットフォームの各サービスを使う人。無料で使う人と、有料プランに申し込む人がいる。
- **運営者**: 管理画面からユーザーとロールを管理する人 (`admin` / `user-manager` ロール)。支援サービスなど Stripe 以外で受けた支援に、手動で有料ロールを付ける。

### 1.3 ビジネスゴール

- 運営コストの一部を、利用者の課金で回収できるようにする。
- 各サービスが、有料ロールを見るだけで無料と有料の出し分けを作れる状態にする。
- Stripe との連携ができる前でも、手動の付与で有料の運用を始められるようにする。

## 2. 機能要件

### 2.1 ユースケース

#### UC-001: 有料プランに申し込む

- **概要**: 利用者が自分で有料プランに申し込み、有料ロールを得る。
- **アクター**: 利用者 (ログイン済み)
- **前提条件**: Google アカウントでログインしている。有効な有料契約がない。
- **正常フロー**:
    1. 利用者がプランの画面で申し込む。
    2. Stripe の決済画面で支払い方法を入力し、支払う。
    3. 元のサービスに戻った時点で、有料ロールが有効になっている。
- **代替フロー**: 決済画面で中止した場合は、何も変わらずプランの画面に戻る。
- **例外フロー**: すでに有効な契約がある場合は、新たな申し込みをさせず、契約の管理へ案内する。

#### UC-002: 契約を管理する

- **概要**: 契約中の利用者が、解約・支払い方法の変更・請求の確認を自分で行う。
- **アクター**: 利用者 (ログイン済み・契約中)
- **正常フロー**:
    1. 利用者がプランの画面から契約の管理を開く。
    2. Stripe の Customer Portal で解約や支払い方法の変更を行う。
    3. 解約した場合も、支払い済みの期間の終わりまでは有料ロールが有効なままになる。

#### UC-003: 契約の変化が自動で反映される

- **概要**: 契約・更新・解約・支払い失敗が、利用者の操作なしに有料ロールへ反映される。
- **アクター**: システム (Stripe からの通知)
- **正常フロー**:
    1. Stripe で契約の状態が変わる。
    2. Stripe からの通知を受け、最新の契約の状態に合わせて課金の権利を書き換える。
    3. 次のロール再取得のときに、利用者の有効なロールが変わる。
- **例外フロー**: 通知が届かない・遅れる・重複する・順序が入れ替わる場合も、最終的には Stripe 上の最新の状態に一致する。

#### UC-004: 有料ロールを手動で付ける

- **概要**: 運営者が、Stripe 以外で受けた支援 (pixiv FANBOX など) に対し、期限つきで有料ロールを付ける。
- **アクター**: 運営者
- **正常フロー**:
    1. 運営者が管理画面で対象のユーザーを開く。
    2. 付けるロールと有効期限を指定して、課金の権利を付ける。
    3. 期限を延ばす、または取り消すこともできる。
- **代替フロー**: 期限が過ぎた権利は、運営者が何もしなくても無効になる。

#### UC-005: 課金に関する公開情報を見る

- **概要**: 誰でも、ログインせずに料金と特定商取引法に基づく表記を確認できる。
- **アクター**: 利用者 (ログイン不要)
- **正常フロー**:
    1. 利用者が料金のページ、または特定商取引法に基づく表記のページを開く。
    2. プランの内容・価格・支払いと解約の条件を確認する。

### 2.2 機能一覧

| 機能ID | 機能名 | 説明 | Phase | 優先度 |
| ------ | ------ | ---- | ----- | ------ |
| F-001 | 課金の権利の保持 | ロール・出どころ・有効期限を持つ「課金の権利」を、手で付けたロールとは別に持つ | P1 | 高 |
| F-002 | 有効なロールの算出 | 手で付けたロールと、期限内の課金の権利のロールを合わせて、セッションのロールとする | P1 | 高 |
| F-003 | 課金の権利の手動管理 | 管理画面から、課金の権利を付ける・期限を延ばす・取り消す | P1 | 高 |
| F-004 | 申し込み | ログイン中の利用者を Stripe の決済画面へ送り、支払いと自サービスのユーザーを結びつける | P2 | 高 |
| F-005 | 契約の管理 | 契約中の利用者を Stripe の Customer Portal へ送る | P2 | 高 |

### 2.3 想定画面の概要

- プラン (auth): 契約の状態、申し込み、契約の管理への入口
- ユーザー編集の課金の権利 (auth 管理画面): 既存のユーザー編集画面に足す
- 料金 (portal)
- 特定商取引法に基づく表記 (portal)

## 3. 非機能要件

### 3.1 パフォーマンス要件

| 項目 | 要件 |
| ---- | ---- |
| ロールの反映 (通常) | 課金の権利が変わってから、既存のロール再取得の間隔 (5 分) 以内にセッションへ反映される |
| ロールの反映 (決済直後) | 決済を終えて戻った時点で反映されている |
| 通知の処理 | Stripe の通知に対して、Stripe の待ち時間内に成功を返す |

### 3.2 セキュリティ要件

- **NFR-SEC-1**: カード情報は自サービスで受け取らない。入力は Stripe の決済画面と Customer Portal で行う。
- **NFR-SEC-2**: Stripe からの通知は、署名を検証してから処理する。検証できないものは処理しない。
- **NFR-SEC-3**: 課金の権利を手動で変更できるのは、ユーザーのロールを変更できる権限を持つ運営者に限る。
- **NFR-SEC-4**: Stripe の秘密鍵と通知の署名鍵は、既存の秘密情報と同じ方法で管理し、リポジトリに置かない。
- **NFR-SEC-5**: 申し込みと契約の管理は、ログイン中の本人の分だけを扱う。他人の契約を操作できない。

### 3.3 可用性要件

| 項目 | 要件 |
| ---- | ---- |
| Stripe の障害時 | すでに付いている課金の権利と、それに基づく有料ロールは影響を受けない |
| 通知の取りこぼし | 一時的に処理に失敗しても、Stripe の再送で最終的に反映される |

### 3.4 保守性・拡張性要件

- **NFR-EXT-1**: 課金の権利の出どころは、Stripe と手動に限らず足せる形にする (将来の支援サービスとの連携を想定)。
- **NFR-EXT-2**: 有料ロールの定義は、既存のロールと同じくコードで管理する。プランと有料ロールの対応は、コードを変えずに変更できる形を目指す。
- **NFR-EXT-3**: 各サービスは、有料かどうかを既存の権限チェックで判定できる。課金のための専用の判定をサービスに持たせない。

### 3.5 その他の非機能要件

- **NFR-PRIV-1**: ログインせずに見られるページから、運営者の本名・住所・電話番号にたどり着けない。特定商取引法に基づく表記では、これらを「請求があれば遅滞なく開示いたします」とする。
- **NFR-COMPAT-1**: dev 環境は develop の版と integration の版が後勝ちで上書きし合う。どちらの版が動いても、もう一方の版が作ったデータでエラーにならない。

## 4. ドメインオブジェクト

| エンティティ | 説明 |
| ----------- | ---- |
| 利用者 | Google アカウントでログインするプラットフォームのユーザー |
| 手動ロール | 運営者が管理画面から付けるロール。今のユーザーのロールそのもの |
| 課金の権利 | 課金によって付くロール。出どころと有効期限を持つ |
| 出どころ | 課金の権利がどこから来たか (Stripe / 手動) |
| 有効なロール | 手動ロールと、期限内の課金の権利のロールを合わせたもの。セッションに載る |
| プラン | 申し込みの単位。どの有料ロールが付くかを決める |
| 契約 | 利用者とプランの間の定期課金。Stripe 上で管理される |
| Stripe の顧客 | Stripe 上の利用者。自サービスの利用者と 1 対 1 で結びつく |

---

## 5. スコープ外

- ❌ 各サービスでの無料と有料の出し分け (どの機能を有料にするか、回数の上限など)。サービスごとに別の Issue で扱う
- ❌ ログインしていない利用者の利用回数の制限
- ❌ 支援サービスとの自動連携 (コード入力・API 連携など)
- ❌ Stripe が送る領収書メールを止めて、自前で通知を送ること
- ❌ 海外の顧客向けの税の処理 (販売代行型の利用を含む)
- ❌ Stripe の本番申請と本番の鍵の設定 (全 Phase を本番に出した後に行う運用作業)

## 6. 用語集

| 用語 | 定義 |
| ---- | ---- |
| 課金の権利 | 課金によって付くロール。手動ロールとは別に持ち、出どころと有効期限を持つ |
| 有料ロール | 課金の権利として付けることを想定したロール |
| Checkout | Stripe が提供する決済画面 |
| Customer Portal | Stripe が提供する、契約者自身が解約や支払い方法の変更を行う画面 |
| Entitlements | Stripe の機能。商品に「機能」を紐づけ、契約に応じて有効な機能の一覧を Stripe が管理する |
